KVM Forum

按年整理 QEMU、KVM 与虚拟化工程实践。精选解读结合原始讲稿，介绍问题、实现机制、实验结果与技术取舍。

KVM Forum 的技术演进

性能、资源利用、安全隔离与兼容性贯穿历届 KVM Forum。多核与云负载要求虚拟机提高并行处理能力；机密计算改变了宿主访问客户机内存和设备的权限；GPU、CXL 等硬件又为地址映射、设备分配和迁移带来新的要求。这些方向长期并行发展，下面按历年议程归纳各时间段的关注点。2026 年继续讨论私有内存管理、客户机内的安全执行环境、异构设备与 ARM64 虚拟化，也提出了 CPU 空闲回收、内存共享和迁移干扰控制等资源管理方案。

2022—2026机密计算、异构设备与资源管理guest_memfd、Arm CCA、COCONUT-SVSM 与 KVM planes 涉及私有内存、可信服务和客户机内部的隔离；GPU、CXL 与可信设备分配要求内核、VMM 和固件协调地址映射与访问权限。CPU 与内存超分、I/O 线程调节、迁移和热更新继续处理资源成本与服务连续性。2026 年的议题包括内存原地转换、vGPU 上游化、ARM64 异构主机迁移与嵌套虚拟化加速，以及减少迁移扫描对业务热页的干扰。
2018—2021安全隔离、轻量化与设备卸载CPU 漏洞缓解与 SEV、TDX 等机密虚机方案要求重新审视内存访问和执行隔离。Firecracker、Kata 与 rust-vmm 探索面向特定负载的精简虚拟机及可复用组件，多进程 QEMU 拆分设备模拟的进程边界。vDPA 等工作推进 I/O 卸载，资源超分、热升级及受保护状态的迁移继续发展。
2014—2017多核扩展、I/O 性能与设备虚拟化NFV、实时业务与大规模部署要求提高吞吐、控制尾延迟。多线程 TCG、IOThread 和网络数据路径优化尝试利用更多 CPU；VFIO、vGPU 与 vIOMMU 处理设备分配和共享。迁移、增量备份、安全加固与内存加密也持续受到关注。
2010—2013设备模型、管理接口与架构扩展qdev、QMP 与 libvirt API 的讨论围绕设备组织和虚机管理展开；virtio/vhost、多队列和透明大页改善 I/O 与内存访问。VFIO、ARM、PowerPC 与嵌套虚拟化扩展了可用硬件和运行场景。资源超分、迁移与容错也已是这一时期的议题。

内存隔离、异构设备与资源效率

guest_memfd / KVM planesGPU / CXL资源调度 / 内存热迁移ARM64 / 嵌套虚拟化I/O / 通信

2026 年的议程延续内存隔离与设备支持的讨论，同时关注资源利用和复杂状态迁移。guest_memfd 原地转换、KVM planes 与 SVSM 安全中断涉及内存访问和执行权限；NVIDIA vGPU 上游化、超级芯片与 CXL Type-2 设备涉及异构硬件接入。CPU 超分、内存分层、EPT 写时复制和 IOThread 动态伸缩讨论资源成本，TDX 与 vGPU 迁移处理受保护状态及设备数据传输。ARM64 异构迁移、嵌套虚拟化和 MSHV 扩展平台支持，AF_VSOCK、virtio-vm 与 Firecracker 设备后端探索通信和 I/O 路径，另有客户机兼容、安全测试及异构系统模拟议题。

CPU 超分：空闲识别与 vCPU 调度

区分三个问题：绑核 vCPU 在 MWAIT 中空闲却仍占用宿主线程，共享超分增加线程调度成本，宿主任务竞争又使繁忙 vCPU 等待。分别解读动态 MWAIT 截获、轻量 vCPU 上下文与 sched_ext 调度，并核对各自的验证范围。

QEMU 内存分层：迁移时保留冷热分布

迁移扫描把冷页重新读入内存，可能挤走业务热页。比较三条分层迁移路径，用业务 p99 与迁移耗时分析保留冷热信息的收益和回收等待的代价。

EPT 写时复制：共享快照与独立写入

让大量沙箱共享初始化快照，同时保持每台 VM 及其 vhost-user 后端的数据一致。解读首次写入、并发缺页、缓冲区准备与增量恢复，并核对内存节省和访问成本。

IOThread 动态伸缩：按负载调节 I/O 线程

固定 I/O 线程配置难以适应负载变化。控制器结合线程利用率、IOPS 和宿主余量进行扩缩容，通过效果检查与回退控制调参风险；队列重绑定的暂停仍是关键成本。

TDX 热迁移：受保护状态的导出与接管

TDX 保护的内存与 vCPU 状态需要平台参与导出和接管。梳理 KVM 接口如何接入 QEMU 迁移流程，以及已跑通的 PoC、脏页扫描限制和待验证的错误恢复。

vGPU 热迁移：缓冲区交接与复制开销

用共享缓冲池减少驱动内部复制，让 GPU DMA 与 QEMU I/O 重叠。结合有无 multifd 的两组实验，解释总迁移时间与停机时间的不同收益，以及 QEMU 侧的后续优化。

内存隔离、GPU 支持与 QEMU 架构演进

guest_memfdGPU / 可信设备Rust / io_uringArm / RISC-V内核热更新迁移 / 资源调度

2025 年的议题覆盖客户机内存隔离、GPU 虚拟化、QEMU 内部改造与多架构支持。guest_memfd 讨论普通及机密虚机的内存管理，SVSM 与设备证明涉及可信服务；NVIDIA vGPU 上游化、Grace Blackwell 和共享设备分配关注新硬件接入。Rust、io_uring 与单一二进制方案探索 QEMU 的实现和构建方式，Arm vCPU 并行启动、Windows on Arm、RISC-V pKVM 涉及平台扩展。VFIO 设备保留、固件热更新、迁移通道和 Shadow ioeventfd 讨论运行维护与 I/O，芯粒调度及大规格虚机则关注资源放置和扩展性。

内核热更新：保留 VFIO 设备与 DMA

大内存与 GPU 虚机难以频繁搬迁。方案在 kexec 期间保留设备、DMA 映射与内存，重建软件状态后恢复客户机；讲稿用 Intel DSA 验证持续 DMA，并交代中断与新 VFIO 接口的未完成部分。

guest_memfd：共享转换与大页的统一管理

以文件描述符管理客户机内存后，普通虚机、机密虚机的共享页和大页开始面对同一套接口问题。重点分析原地转换为什么需要严格的映射约束，以及局部共享怎样影响大页的生命周期。

普通虚机的内存隔离：移除宿主直接映射

客户机内存可从宿主内核直接映射中移除，同时保留 VMM 需要的用户态访问。解读 guest_memfd 如何绕开传统 GUP 路径，以及 TLB 刷新、快照恢复和 kvm-clock 给该方案带来的约束。

io_uring：让 QEMU 事件循环统一提交异步操作

把 io_uring 从磁盘后端扩展到 AioContext，使 eventfd、文件和自定义命令复用提交与完成处理。区分 eventfd 微基准约 30% 的提升与尚不明确的整机存储收益，讨论批处理和通知延迟的取舍。

Shadow ioeventfd：在 KVM 内传递门铃值

NVMe 门铃需要携带队列尾指针，普通 ioeventfd 只传通知。新路径由 KVM 保存写入值并唤醒后端，省去 QEMU 往返；结合 Windows 随机读实验，分析异步通知、覆盖语义与实际性能收益。

Arm 多核启动：并行初始化与独立启动上下文

逐核启动会累积固件和寄存器访问开销，共用启动变量还可能被延迟运行的 vCPU 破坏。方案通过 PSCI 传递独立上下文，把本地初始化并行化，并在同步点之后更新全局 CPU 特性。

机密虚机、异构设备与性能维护

SVSM / SEV-SNPGPU / CXL / AI多队列 / 存储内存超分迁移 / 内核热更新模拟 / 多架构

2024 年的议程同时关注机密虚机与异构硬件。SVSM、VMPL、固件证明、SNP 迁移和安全中断讨论受保护状态的管理，Hyper-V VSM 与 Arm TrustZone 涉及客户机内的隔离需求。GPU、CXL、SR-IOV、AI 基础设施和混合 CPU 带来设备分配与资源管理议题。IOThread 多队列映射、进程外存储、内存超分、设备状态并行迁移及 Akamai 内核热更新面向性能与维护成本；TCG 插件、微架构研究、车载平台、Windows on Arm 和测试扩展了模拟与验证场景。

virtio-blk 多队列：把请求分配到多个 IOThread

客户机有多个 virtqueue，宿主仍可能由一个线程处理全部队列。QEMU 9.0 的队列映射打通宿主并行路径；结合 Optane 随机读与数据库测试，说明线程数量、CPU 绑核和剩余带宽如何决定收益。

进程外存储：性能、隔离与管理接口的取舍

NBD、FUSE、vhost-user、vDPA 与 ublk 提供不同的进程外存储路径。对比不同后端的拷贝次数、权限和共享内存要求，说明部署时如何权衡 IOPS 与管理成本。

userfaultfd 内存超分：让换页策略与迁移协调

外部内存控制器掌握页面驻留与换出位置，让迁移避免重新读入全部冷页。讲稿同时展示 SATA SSD 上的明显收益、RAM-disk 与内核编译中的退化，揭示用户态缺页路径自身的成本。

设备状态并行迁移：减少多 VF 的停机时间

VFIO 设备的大量状态挤在单条迁移流中，会延长切换停机。方案把设备状态读取、multifd 传输和恢复分开并行处理；从一到四个 ConnectX-7 VF 的数据分析收益与通道数量的边界。

Akamai 内核热更新：原机保留内存并恢复虚机

找不到兼容迁移目标时，通过持久保留的内存后端和 QEMU CPR，在原机更换内核并恢复客户机。重点讨论设备重初始化、NUMA、时间服务和启动编排对停机窗口的影响。

SNP 迁移：在受保护上下文中打包内存

宿主不能直接读取 SNP 私有内存，迁移打包工作需要可信执行上下文。比较 Mirror VM 与 Shadow vCPU，说明 guest_memfd 地址空间共享、身份验证和状态收尾为何成为关键配套。

SNP 中断保护：让可信组件决定注入

内存加密后，不可信宿主仍可能利用异常注入影响客户机。Restricted Injection 和 Alternate Injection 将接受与转交中断的职责移入可信组件，带来 SVSM、VMPL 与客户机 APIC 协议的协作要求。

机密计算、Arm 虚拟化与 I/O 并行

2023 年的机密计算讨论深入到内存与可信服务：文件描述符管理的私有页涉及记账和迁移，Arm CCA、COCONUT-SVSM、vTPM 与 SEV-TIO 涉及信任链及设备访问。Arm 宿主改造、macOS 支持、CPU 模型与热插拔，以及 Windows Credential Guard，反映出平台和客户机兼容需求。块层多队列、vDPA 影子 virtqueue 与 virtio-fs 讨论 I/O 并行、状态管理和文件共享；eBPF 退出分析、TCG/LLVM 及 Kata Containers 则覆盖调试、模拟与容器集成。

块层多队列：让多个 IOThread 安全共享块图

客户机多队列需要块层真正支持并发。围绕 AioContext 大锁、块图读写锁和协程约束，分析 QEMU 的线程安全改造。对比原型的随机读数据与通用块层需要保护的共享状态。

vDPA 热迁移：用影子队列保存设备状态

硬件直接处理队列后，QEMU 容易失去对设备配置和 DMA 写入的观察。影子队列把必要的控制与数据路径纳入软件记录，并展示跨 Xilinx、Mellanox 网卡迁移的实现条件。

私有内存：补上页面迁移与资源记账

机密虚机的私有页脱离普通用户态映射，传统反向映射、NUMA 策略和进程 RSS 统计随之失效。通过 40 GB SNP 虚机的观察，解释 guest_memfd 与 Linux 内存管理之间需要补齐的接口。

Arm CCA：KVM 如何管理不可读取的虚机

Realm 把私有内存与执行状态交给可信固件管理，KVM 仍负责资源调度。沿创建、启动、共享 I/O 和销毁过程，分析 RMM、KVM 与客户机的职责，以及早期实现对换页和迁移的限制。

COCONUT-SVSM：在机密虚机内部提供可信服务

客户机无法继续信任宿主模拟的 TPM 和中断来源，需要内部可信服务层。介绍 VMPL 隔离、Rust 核心与用户态模块的设计，区分当时已能运行的基础功能和仍在建设的模块与持久化能力。

eBPF 处理 MMIO：缩短虚机与宿主的反馈路径

频率与调度反馈对响应延迟敏感，绕经用户态设备模拟会增加成本。原型将受限 MMIO 回调放入 eBPF，借 vCPUFreq 验证收益，同时暴露中断、异步操作、权限和长期 ABI 的设计难题。

可信执行、I/O 接口与虚机生命周期

机密容器 / pKVMSEV-SNP / TDXIOMMUFD网络 / 存储接口内存扩展性启动 / 在线更新

2022 年的议程广泛讨论可信执行环境：机密容器、Android 与 x86 上的 pKVM、SEV-SNP、TDX、SVSM，以及证明和安全 I/O，分别涉及隔离、可信服务与设备访问。Arm MMU 扩展性、通用页表设计、异步销毁、快速启动和 CPU 动态调整关注虚拟机整个生命周期。IOMMUFD、vDPA、SPDK vfio-user、QSD、libblkio 与 passt 讨论设备、存储和网络接口；VMM 在线升级、保留 IOMMU 状态的内核更新、RISC-V 中断及客户机 ABI 测试补充了平台与运维议题。

Arm 大虚机迁移：控制页表拆分与 TLB 广播

48 vCPU、192 GiB 虚机在启用脏页跟踪时出现严重停顿。分析 MMU 锁、大页拆分与 Arm TLB 失效规则的叠加成本，说明并行缺页处理和限速拆分怎样共同改善运行连续性。

IOMMUFD：重建直通设备的地址空间接口

设备直通需要共享地址空间、嵌套转换和缺页上报，旧 VFIO 容器接口逐渐难以扩展。沿 IOAS、硬件页表和设备绑定关系，解读新接口的设计目的与 2022 年尚未稳定的能力边界。

pKVM：让宿主内核受内存访问规则约束

pKVM 在 EL2 为宿主和客户机分别管理访问权限，把敏感 vCPU 状态保存在宿主不可读取的对象中。沿页面所有权、MMIO 和销毁过程，说明隔离实现，以及与普通 Linux 内存访问的冲突。

passt：把虚机网络接入普通宿主套接字

KubeVirt 的网络需要与 Pod 内的代理、安全策略和地址模型协作。passt 把以太帧转换为宿主套接字操作，在无需创建特权网络接口的条件下工作，同时通过批量处理控制用户态网络的成本。

QSD 与 libblkio：拆开虚机和存储的生命周期

存储任务常常需要在虚机关闭后继续执行，多个虚机也可能共享镜像链。QSD 抽出块层服务，libblkio 提供设备访问接口；比较直接导出队列与经过 QEMU 块层的路径及其取舍。

内核热更新：跨 kexec 保留 DMA 映射

更换宿主内核时，直通设备可能继续进行 DMA。方案保留客户机内存、IOMMU 页表和 PCI 状态，在新内核中重建中断连接；重点辨析原型验证范围与真实硬件上的安全要求。

机密计算、设备卸载与资源管理

SEV-SNPTDX内存超分 / 迁移vDPA / VDUSEvfio-user容器 / 运维

2021 年的机密计算议题覆盖 SEV-SNP、TDX、客户机内存映射、安全启动、证明及加密镜像，讨论范围从处理器机制延伸到启动与运行管理。内存超分、脏页跟踪和迁移收敛关注大规格实例的资源利用与停机时间。vfio-user、多进程 QEMU、VDUSE、vDPA 和 SPDK 探索设备后端与硬件卸载，virtio-fs 高可用及 eBPF RSS 涉及存储、网络的实际部署。libvirt 热升级、Kata、libkrun、rust-vmm 和性能回归、Windows 测试则覆盖管理与验证。

生产内存超分：组合 balloon、换页与工作集估计

单靠 balloon 依赖客户机配合，单靠宿主换页又容易触发双重换页。生产方案结合 cgroup 限额、空闲页采样和备用内存池，重点处理突发需求、失效回退以及迁移对工作集的扰动。

大内存迁移：脏页位图也会成为瓶颈

TB 级虚机的脏页位图达到数百 MB，多层复制和原子操作会消耗可观时间。结合 3 TB 虚机观察与位图微基准，区分写入捕获、变化上报和用户态归并，分析应当优化哪一层。

VDUSE：让用户态设备服务虚机和容器

同一用户态块设备后端需要同时接入虚机与宿主应用。VDUSE 复用 vDPA 控制接口，以共享映射或回弹缓冲区连接数据路径，说明 IOTLB、通知与设备生命周期的协作方式。

SEV-SNP：把页面所有权纳入硬件检查

2013 年的讨论从虚拟机内部性能延伸到桌面和云平台。Nested EPT、Shadow Turtles 与 QEMU 多线程改造关注嵌套运行、共享状态及并发执行；Virgil3D、GPU 分配和 Spice 探索图形加速与远程显示。RDMA 迁移、COLO 容错和内存气球讨论实例迁移、故障接管与资源调节。管理侧包含 libvirt、QAPI、OpenStack、oVirt 和 Kimchi，架构侧继续推进 s390 与 POWER 支持，反映出设备能力、管理接口和应用场景需要共同配套。

Nested EPT：合成两层物理地址转换

嵌套客户机引入第三层地址关系，硬件却不能直接遍历所有层次。方案合成 L2 物理地址到宿主物理地址的映射，让 L2 自行管理进程页表；讲稿还解释指令模拟为何需要另一套软件翻译上下文。

QEMU 多线程：内存视图、对象寿命与无锁访问

设备数据面绕开全局锁后，地址映射与对象回收需要明确同步。讲稿用 FlatView、引用计数和 RCU 解释设备如何安全移除；动态 BAR 的例子说明，即使回调本身线程安全，地址映射仍可能在访问期间改变。

Virgil3D：通过 Virtio 提交图形命令

客户机 Mesa 将图形状态和绘制命令送到宿主渲染器，再转换为宿主 OpenGL 调用。讲稿展示 virtio-gpu 与 3D 渲染的分工，以及资源、着色器、完成通知和宿主驱动安全边界的早期设计。

COLO：以对外响应校验虚拟机副本

主备虚拟机接收相同输入，输出匹配时对外放行，发生差异再同步检查点。方案减少逐指令确定性执行的要求，但网络比较、磁盘缓存和故障切换必须共同维持一致性；性能图在原稿中标为预测。

短时空闲：消息负载中的 vCPU 切换成本

短消息处理频繁进入等待，完整保存状态与调度可能比实际空闲更昂贵。讲稿用逐步简化路径的实验定位开销，再比较客户机轮询、延迟 FPU 保存与延迟上下文切换的方案，保留饥饿和功耗风险。

大规模虚机、I/O 并行与多架构支持

大规模 SMPMemoryRegion / QOMAPICv多队列 I/OArm / POWER / s390云管理

2012 年的一个重要方向是扩大虚拟机规模，同时减少共享数据结构和串行 I/O 带来的限制。大规模 SMP、反向映射、APICv 与网络、块设备多队列分别涉及内存管理、中断和并行处理；MemoryRegion、QOM 与 BQL 讨论 QEMU 内部接口及并发改造。Q35、OVMF、VFIO 和存储镜像操作丰富了虚拟平台的设备与固件能力，Arm、POWER、s390 相关工作拓展架构支持。OpenStack、oVirt 及测试议题则关注这些能力在云管理中的组合与验证。

QEMU 内存 API：把总线拓扑变成地址视图

真实设备地址经过桥、别名和区域覆盖，简单按页登记很难正确表达。新 MemoryRegion 模型由设备声明局部区域、核心生成平坦视图，再通知 KVM 和设备后端，为多地址空间与并发读取建立基础。

APICv：让硬件处理更多虚拟中断状态

APIC 寄存器访问、中断窗口和 EOI 都可能造成退出。讲稿逐项解释寄存器虚拟化、虚拟中断投递与 Posted Interrupt 的职责，尤其区分目标 vCPU 免退出和发送侧仍需软件处理的情况。

Virtio-net 多队列：从网卡队列到宿主线程

单队列让客户机与 vhost 的处理能力集中在少量 CPU。方案贯通 Virtio 队列对、QEMU、TAP 文件描述符与多个 vhost 线程，并用事务与流式负载展示并行度提高后可能出现的相反结果。

KVM/ARM：Hyp 模式、二级页表与设备协作

早期 Armv7 硬件虚拟化引入 Hyp 模式和 Stage-2，但完整 Linux 宿主仍运行在普通内核模式。讲稿沿世界切换、缺页、MMIO 和 VGIC 说明两部分 KVM 如何协作，并交代当时上游评审状态。

绕过 BQL：低延迟设备路径需要怎样的锁规则

细化设备锁可以降低全局争用，却会遇到回调嵌套、热拔除和前后端反向加锁。讲稿以 RTC 定时器原型贯通独立路径，解释生命周期和锁顺序为何必须一起设计，同时列明尚未支持的操作。

设备分配、存储管理与企业应用

VFIOvirtio-scsi存储 / 备份实时 / HPC管理工具多架构

2011 年的议程兼顾设备接口改造与实际部署。VFIO、图形设备分配和 virtio-scsi 讨论不同设备的接入方式；qcow2、在线块复制、备份与 I/O 限速关注虚拟磁盘的一致性和运行管理。实时虚拟机、HPC 与企业负载把响应延迟、资源隔离和扩展性带入性能讨论，libvirt、VDSM 等管理工具则处理实例配置与生命周期。POWER7、嵌入式平台、SmartOS 和 Spice 相关议题进一步展示了服务器之外的系统集成需求。

VFIO：把设备分配从 KVM 中拆出来

早期设备分配依赖 KVM、PCI sysfs 与零散权限规则。VFIO 提案用设备驱动统一配置、区域访问、IOMMU 和事件通知，既服务虚拟机也服务用户态驱动；讲稿同时暴露隔离组和跨架构支持仍待定的问题。

qcow2：元数据一致性与异步 I/O 的改造

映射和引用计数更新必须保持崩溃一致性，逐次同步却会拖慢分配并阻塞 vCPU。讲稿解释写回元数据缓存与协程如何分别改善吞吐和响应，并区分当时发布能力与 qcow2 v3 的后续设想。

virtio-scsi：把存储功能放回 SCSI 协议

一盘一 PCI 设备和有限 SCSI 透传制约了早期 virtio-blk 的扩展。virtio-scsi 用命令、控制和事件队列承载 SCSI 语义，允许一个控制器管理更多设备，并比较 QEMU 与内核 target 两条后端路径。

实时虚拟机：定位用户态设备模拟的长尾

客户机定时唤醒和外部设备响应需要分别测量。原稿通过直通与模拟网卡实验定位 QEMU 全局锁和同步操作的影响，再提出 CPU 状态局部化、独立设备上下文及中断快速路径。

QEMU I/O 限速：统一后端控制与执行成本

宿主块设备限速难以统一覆盖 NFS 等后端。QEMU 在块层排队并延迟提交，可以按客户机请求控制 IOPS 或带宽；实验同时比较缓存模式、限额偏差和 CPU 成本，展示统一控制接口的代价。

设备模型、管理接口与虚拟化扩展

qdevQMPvirtio / vhost内存管理迁移 / 容错多架构

2010 年的议题围绕虚拟机的设备模型、管理接口和运行效率展开。qdev、QMP 与 VMState 分别整理设备创建、外部控制和迁移状态；virtio、vhost-net 与 PCI 设备分配讨论网络及设备访问路径。透明大页、异步缺页和内存超分关注地址转换成本与宿主资源利用，热迁移和 Kemari 容错探索服务连续性。Spice、PowerPC、嵌入式平台及 Ganeti 管理实践也进入议程，呈现出 QEMU/KVM 从基本执行能力向更多硬件、桌面和集群场景扩展的方向。

qdev：统一 QEMU 设备的创建与管理

设备参数、初始化和热插拔原本分散在不同路径。qdev 用设备树、属性和生命周期回调统一管理入口；原稿通过串口代码说明改造方式，也指出热拔除完成通知与设备标识仍需完善。

透明大页：降低虚拟机地址转换成本

客户机与宿主的两级页表放大了地址转换成本。透明大页通过按需分配、后台合并和回退机制扩大 TLB 覆盖；原稿用定制编译负载比较两层大页组合，并讨论碎片、回收和内存占用。

VMState：描述可迁移的设备状态

手工维护保存和加载函数容易产生字段顺序与版本错误。VMState 把状态结构、版本和可选子节集中描述，并通过加载后回调恢复派生状态；接口简化仍需要兼容性与在途 I/O 测试支撑。

QMP：建立面向管理程序的控制接口

管理程序需要稳定的机器接口，人工 monitor 文本难以承担这个角色。QMP 用 JSON 表达命令、结果、错误和异步事件；讲稿还分析迁移、热拔除等长操作的完成语义与接口演进问题。

异步缺页：让宿主换页不再阻塞整个 vCPU

宿主换入一个客户机页面时，同一 vCPU 上的其他任务也可能停顿。异步缺页让客户机调度器获知等待与完成事件，切换到仍可运行的任务；原型以重度内存超分实验验证这种协作。
