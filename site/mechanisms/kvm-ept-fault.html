前言

客户机物理地址描述虚拟机内的地址空间。Intel EPT 将它映射到宿主物理内存；KVM 建立并维护这层页表，QEMU 则向 KVM 登记哪些客户机地址对应自己的 RAM 映射。QEMU 组织内存布局，KVM 维护映射，处理器完成实际访存。

本文跟踪普通虚拟机对一页 RAM 的首次访问，以 x86、Intel EPT 和 KVM TDP MMU 为例。后备内存采用 QEMU 可访问的匿名内存或文件映射，地址示例使用 4 KiB 页；私有内存与嵌套虚拟化另有处理路径。

源码版本：QEMU 10.2.0、Linux 6.18。

两级转换与宿主映射

客户机页表把客户机虚拟地址 GVA 转成客户机物理地址 GPA，EPT 再把 GPA 转成宿主物理地址 HPA。客户机页表页本身也放在客户机物理内存中，因此硬件读取这些页表项时，同样需要 EPT 转换。TLB 与页表遍历缓存减少了重复遍历，不能把这条路径理解为每次访问都由软件查询两张表。

QEMU 的宿主虚拟地址 HVA 用于定位 RAM 后备内存。KVM 根据 HVA 查询宿主内存管理，取得当前物理页，再建立 EPT。已建立映射后的客户机访存直接使用硬件转换；HVA 不出现在 EPT 页表项中，也不会作为客户机的第三层硬件地址转换。KVM MMU 的地址空间说明

EPT 的读、写、执行权限与客户机页表权限共同约束访问。客户机允许写入，仍可能被 EPT 写保护拦截；EPT 允许写入，也不能绕过客户机页表的只读限制。设备 DMA 使用的 IOMMU 映射是另一条路径，见VFIO 的 DMA 地址转换与隔离。

内存注册与关键结构

QEMU 的 KVMSlot 保存客户机地址范围及 RAM 指针，kvm_set_user_memory_region() 将其转成 ioctl 参数。注册的结果是建立地址范围关系，通常不会立即为范围内每一页分配宿主物理页或填满 EPT。QEMU 内存注册

用户态字段宽度与作用本例
slot32 位；低 16 位是槽 ID，高 16 位用于支持多地址空间的配置0
flags32 位；脏页记录、只读等属性0，普通可写 RAM
guest_phys_addr64 位；GPA 起始地址0x00400000
memory_size64 位；字节数，设为 0 表示删除槽0x00200000，2 MiB
userspace_addr64 位；QEMU 进程中的 HVA 起点0x7f0000000000

这些字段同时存在于 kvm_userspace_memory_region 和扩展的 kvm_userspace_memory_region2。后者另有 guest_memfd、guest_memfd_offset 等字段；其使用受相应标志与能力控制，普通 HVA 后备 RAM 不需要借助 guest_memfd 定位。QEMU 可以根据内核能力选择 REGION2 ioctl，这本身不表示虚拟机使用私有内存。ABI 定义

内核对象或值关键内容参与的操作
kvm_memory_slotbase_gfn、npages、userspace_addr、flags、id按客户机页号查找 RAM 范围，计算 HVA，关联脏页记录
kvm_page_faultgfn、slot、pfn、write、map_writable、mmu_seq保存本次访存类型、后备页和失效序号，贯穿缺页处理

SPTEKVM 管理的页表项；本路径中对应 EPT 项，包含物理地址、权限、页级别及状态位非叶子项指向下级页表；叶子项把 GPA 页映射到宿主页

memslot 描述一段地址范围，SPTE 描述某一级硬件映射。一个槽可以对应很多 EPT 叶子项；相邻 HVA 连续也不保证宿主物理页连续。只读槽、宿主页是否可写和 KVM 为记录脏页设置的写保护，还会影响最终的写权限。

EPT 页表页也是具体的数据结构：一个 4 KiB 页容纳 512 个 64 位表项，每一级从 GPA 中取 9 位选择下一项。以四级 EPT、4 KiB 叶子为例，依次使用 GPA 的位 47–39、38–30、29–21、20–12，最后 12 位是页内偏移。非叶子项保存下级页表的宿主物理地址，叶子项保存目标页的宿主物理地址；大页可在更高层终止遍历。页表项与层级

一页 RAM 的首次访问

假设客户机页表已把 GVA 0x0000000040203080 映射到 GPA 0x00403080，客户机页表相关的 EPT 映射也已存在，只有目标数据页尚未建立 EPT 叶子项。处理器因第二级转换无法完成而退出，VMX 后端读取 GPA 和访问类型，进入 KVM 缺页处理。

页大小                  = 0x1000 B = 4 KiB
访问 GPA                 = 0x00403080
GFN                      = 0x403
页内偏移                 = 0x080 B

memslot.base_gfn          = 0x400
memslot.npages            = 0x200 = 512 页
槽内页号                 = 0x403 - 0x400 = 3
后备页 HVA               = 0x7f0000000000 + 3 × 0x1000
                         = 0x7f0000003000

宿主内存管理返回 PFN     = 0x21000
EPT 叶子映射             = GPA 页 0x00403000 → HPA 页 0x21000000
本次访问的 HPA           = 0x21000000 + 0x080
                         = 0x21000080

__gfn_to_hva_memslot() 完成槽内偏移计算；随后 __kvm_faultin_pfn() 经宿主取页路径解析 PFN。后备页尚未驻留时，可能需要分配、调入或等待 I/O；KVM 也存在异步缺页分支。普通 RAM 的这次建图获取页引用，完成后释放临时引用，不能把它理解为将整个虚拟机内存永久 pin 在物理地址上。GFN → HVA、宿主取页

在 TDP MMU 慢路径中，KVM 取得 PFN 后获取 mmu_lock 读锁，确认本次结果没有失效，再逐级创建缺少的页表页，以原子操作安装叶子 SPTE。若其他 vCPU 已建立映射或修改同一项，会检查结果或重试；成功后重新进入客户机，由处理器重试原来的访存。通常无需返回 QEMU，也不需要修改客户机页表。缺页入口、叶子项安装

缺页、写保护与 MMIO

EPT violation 说明第二级转换或访问权限未能满足请求，它的处理结果取决于地址与映射状态。硬件退出次数不能直接当作客户机缺页次数，也不能直接当作 QEMU 设备请求次数。

场景关键区别处理方向
客户机 #PF客户机自己的页表缺失或权限不允许普通 EPT 模式下由客户机异常机制处理；客户机内核决定建图、调页或报告非法访问
RAM 的 EPT 缺页GPA 在有效 RAM 槽内，但第二级映射缺失KVM 解析后备页、建立 EPT，再执行原访存
RAM 写保护已有映射，但当前 EPT 项不可写区分脏页跟踪、页跟踪及真实只读属性，按原因记录、恢复权限或进入模拟
GPA 未落入 RAM 槽可能是设备地址，也可能是未映射空洞走无槽及 MMIO 模拟路径，由内核设备或 QEMU 地址空间继续处理；不会自动分配一页 RAM
宿主后备页无法取得RAM 槽存在，但宿主内存解析出错根据错误类型重试、处理信号或报错，不能一律转换成普通 MMIO

例如迁移开启写保护式脏页跟踪后，客户机对已存在 RAM 页的首次写入会触发 EPT 处理，KVM 记录页被修改，再允许后续写入。KVM_MEM_READONLY 则声明槽的只读属性：x86 对它的写请求可交给用户态 MMIO 处理，不应像脏页记录那样随意恢复可写。脏页记录也可以结合硬件辅助机制，不能把所有记录模式都归结为逐页写退出。只读槽约定

无槽访问还可能缓存成特殊 MMIO SPTE，后续通过 EPT misconfiguration 等路径识别；“看到 EPT 退出”不足以判断是否需要 QEMU。对应实现见 kvm_handle_noslot_fault() 与 handle_ept_misconfig()。用户态往返见vCPU 退出处理，迁移脏页交接见Dirty Ring。

宿主页变化与映射失效

QEMU 的 HVA 可以保持不变，背后的宿主物理页却因回收、页迁移或映射变更而改变。如果 KVM 继续使用旧 SPTE，客户机就可能访问错误的物理页。清理 CPU 缓存的转换结果还不够：已有页表项必须失效，正在处理的缺页也不能把旧 PFN 重新填回去。

宿主内存管理通过 MMU notifier 通知 KVM 某个 HVA 范围即将失效。KVM 找到相交 memslot，把范围转换成 GFN，记录失效进行中，撤销对应叶子映射，并完成所需的远端 TLB 失效。失效结束时推进 mmu_invalidate_seq。范围失效与序号更新

缺页线程先保存 fault.mmu_seq，再解析 PFN；锁外预检查尽早避开正在失效的范围，锁内 is_page_fault_stale() 最后检查根是否过期、目标 GFN 是否正在失效，以及序号是否变化。发现冲突就释放本次取页结果并重试。锁外检查只用于减少争用，不能替代最后的锁内判断。检查顺序、序号与范围判定

memslot 本身的移动、删除也需要使旧映射失效；槽的生命周期通过专门的更新同步保护。由此，HVA → PFN 查询、EPT 页表修改与宿主内存生命周期形成同一套一致性约束，才能支持按需分配、回收与迁移。

关键源码

从 VMX 退出入口向下追踪时，可以把路径分为“解释访问、解析后备、提交映射”三段。它们分别回答客户机要做什么、宿主能提供哪一页，以及当前能否安全地把这一页交给硬件。

阶段源码入口与操作
读取硬件信息handle_ept_violation() 读取 GPA；__vmx_handle_ept_violation() 将读、写、取指和页表遍历信息转成 KVM 使用的标志。
选择处理分支kvm_mmu_page_fault() 区分 MMIO 缓存、正常缺页与写保护；需要模拟时进入指令模拟器。
取得后备页kvm_mmu_faultin_pfn() 保存失效序号，检查槽与地址属性，通过宿主内存管理取得 PFN 及实际可写性。
验证并提交kvm_tdp_mmu_page_fault() 完成锁内过期检查，调用建图函数，最后释放本次取页持有的引用。
安装页表层级kvm_tdp_mmu_map() 调整目标页级别，遍历并补充中间页表，再安装叶子项。
组合权限与地址make_spte() 将 PFN、宿主可写性、访问权限与跟踪策略组合成页表项，必要时记录脏页。

快速缺页修复会尝试直接调整已有项，首次建图通常进入上述慢路径。返回 RET_PF_FIXED 表示映射已修复，RET_PF_RETRY 表示需要重试，RET_PF_EMULATE 才转向指令模拟；这些内核结果与返回用户态的 KVM_EXIT_MMIO 属于不同层次。

从影子页表到 TDP MMU

早期影子页表把客户机页表和宿主映射合成为 GVA → HPA 的页表供硬件使用。客户机修改页表、切换地址空间时，KVM 需要维护合成结果，涉及页表写跟踪、同步和反向映射。EPT 把 GPA → HPA 单独交给硬件，客户机可以直接维护自己的 GVA → GPA 页表，减少软件跟踪客户机页表变化的工作。

2008 年，EPT 支持进入 KVM，随 Linux 2.6.26 发布。第二级页表也带来额外的遍历成本：客户机页表访问本身仍需经过 EPT，缓存未命中时尤其明显。TLB、页表遍历缓存以及满足对齐和后备条件的大页可以减少开销；大页又会与细粒度写保护、脏页记录和回收发生权衡。

2020 年，Linux 5.10 纳入新的 TDP MMU，包含独立的缺页建图路径，初期默认关闭。这是 KVM 管理 EPT / NPT 页表的软件实现演进：利用 GPA 索引的树结构简化管理，减少传统实现中维护反向映射等通用逻辑的负担。硬件 EPT 与这个软件实现不在同一时间引入。

2021 年，Linux 5.12 纳入并行缺页处理，让 TDP 缺页路径以读模式持有 MMU 锁。大量 vCPU 同时首次访问内存时，多个缺页处理可以并行建图，降低集中锁争用；对同一页表项的竞争仍需检测与重试。

当前代码中，RCU 保护页表遍历期间的对象生命周期，原子更新处理多个线程对同一 SPTE 的竞争；失效等操作仍需要相应同步。并行化也增加了重试、延迟释放及根生命周期管理的复杂度。页表遍历与并发安装

分析访存性能时，可先区分客户机 #PF、宿主取页等待、EPT 建图、写保护退出与 TLB 未命中。启动时大量首次访问、迁移时启用脏页跟踪、宿主页回收之后重新建图，虽然都可能增加 KVM MMU 工作量，优化手段却不相同。预分配后备内存主要减少运行时宿主分配等待；它本身不保证所有 EPT 都已预建。大页可以扩大 TLB 覆盖范围，但需要同时检查宿主后备、地址对齐及跟踪粒度。

大页条件与迁移期间的粒度变化见KVM 大页映射的建立、拆分与恢复，其中逐步展示 2 MiB 叶子与 512 个 4 KiB 叶子的转换。
