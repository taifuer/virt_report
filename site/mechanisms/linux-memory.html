一、映射与实际驻留

为进程建立一段虚拟地址，并不等于立即为每个字节准备物理内存。以私有匿名 mmap() 为例：内核先记录可访问的范围和权限，页面可以在首次访问时才建立。这里讨论普通按需分页路径，不包含预填充、锁页等特殊要求。

理解这层差异，才能区分进程地址空间、RSS、页缓存和虚拟机配置内存。下文先从一个 Linux 进程观察，再把同样的机制放到 Guest 和宿主两侧。

源码版本：Linux 6.18。

二、从按需分页到多核内存管理

Linux 内存管理并不是一张页表逐渐变大。地址空间管理、物理页分配、文件缓存与回收各有自己的数据结构；随着内存容量、CPU 数量和映射数量增长，这些层分别演进。

演变主线机制变化动机与取舍
按需分页与写时复制映射先描述地址范围，访问时才建立驻留页；fork 后可先共享私有页，写入时再分离避免为未访问空间分配、为未修改页复制；代价被移动到缺页路径，第一次访问会更慢
2.6 时代的地址空间与缓存管理VMA 使用链表、红黑树及查找缓存；文件页缓存、反向映射和回收协作既要从地址找页，也要从待回收页找到映射它的进程。共享映射和锁竞争使回收不只是释放一块内存
大内存、SMP 与 NUMA按节点与 zone 管理页面，配合每 CPU 缓存、大页和页面迁移降低争用和地址转换成本，但需要处理远端访问、连续内存碎片和大页拆分
近年的 5.x / 6.xfolio 表达一组页面，Maple Tree 管理 VMA 区间，可选 MGLRU 改进冷热页识别分别优化页面管理粒度、映射查找与回收策略；它们作用于不同层，不是同一种“新分页算法”

可直接比较 2.6.12 的 mm_struct 中 mmap 与 mm_rb，和当前 Maple Tree 的区间索引。Maple Tree 替换的是内核查找 VMA 的组织方式，不是 CPU 硬件使用的多级页表；一次合法访存也不会逐次遍历 VMA 树。

三、地址、页表与物理页

对象记录内容不等于
mm_struct / VMA地址空间以及各段映射的范围、权限和后备对象每个虚拟页都已有驻留页
页表项 PTE 等地址转换、访问权限和页面状态所有条目都有效，也不保证全是普通 RAM
page / folio物理页面及内核管理状态；folio 可管理一组连续页面一个应用对象或一条磁盘请求
TLB处理器缓存的地址转换信息页面内容的缓存，或页表本身

在 x86 等硬件查表架构上，TLB 未命中通常先由硬件遍历页表；映射有效时无需进入内核。缺页异常意味着转换或权限需要软件处理，既可能是正常的按需分配，也可能最终成为非法访问。不能把 TLB miss、page fault 和磁盘换入画成同一件事。

地址拆分与硬件查表

以 x86-64 的 4 KiB 基页为例，虚拟地址 0x400123 的页内偏移是 0x123。若页表把该虚拟页映射到物理页基址 0x12a000，最终物理地址就是 0x12a123。硬件利用页表根和各级索引找到映射，检查访问权限，再结合偏移访存；不会为了每次 load/store 都调用一次 Linux 分配器。

多级页表让大段未使用地址不必拥有完整的底层页表。Linux 通用代码表达 PGD、P4D、PUD、PMD、PTE 五级，实际不用的级会折叠；不是每台机器都做五级硬件遍历。大页则可在较高一级直接结束查表。VMA 记录的是“这段地址应该如何处理”，CPU 正常访存消费的是页表中的实际映射。见 页表层级与硬件查表。

文件的 address_space 以文件偏移关联页缓存；进程页表则以虚拟地址关联页面。同一文件页可以被多个进程映射，匿名页也可因 fork 暂时共享。回收时需要反向映射检查或撤销相关 PTE，并处理 TLB 失效，不能只把物理页从一个列表删掉。

四、首次访问与写时复制

do_mmap() 建立映射约定；访问触发缺页后，内核检查地址与权限，并进入 handle_mm_fault() 等路径。匿名页首次读取可以使用共享零页；首次写入通常需要分配可写的私有页，再安装页表项并重新执行导致异常的指令。

do_anonymous_page() 展示零页与实际分配的区别。文件映射则需要找到文件对应的页缓存；若数据不在内存，可能发起 I/O 并等待。这就是部分缺页只消耗内存管理工作，另一些却会被存储延迟拖慢的原因。

合法写入与写保护异常

fork() 后，私有可写 VMA 的约定可以仍是“允许写”，但父子进程的 PTE 被设为只读，用来截住第一次修改。下面以一个普通匿名页 P、父子进程都继续持有映射为例：

子进程页表更新前，父子读取的都是 P；发生写保护异常时，内核才为子进程分配 Q，复制旧内容、安装可写映射并重试原写指令。之后子进程继续写 Q，不会每写一个字节都再复制一遍。父进程依然看到 P 中的旧内容：被分离的是页面和映射，不是把父进程整个地址空间重新复制一次。

do_wp_page() 会判断页面是否已可独占复用；如果不再需要保留共享副本，可能只恢复写权限。相反，VMA 本身不允许写时，异常不能用 COW 掩盖。修改映射还必须同步相应 TLB 状态，否则 CPU 可能继续使用旧权限或旧地址。

以 1 MiB 私有匿名映射为例，若按 4 KiB 基页处理、没有预填充或大页，则覆盖 256 个虚拟页。刚完成 mmap 时不必有 256 个私有驻留页；首次写遍它们才逐步建立实际页面。这里的 256 是地址范围的算术分解，不是对所有机器缺页次数的预测：大页、提前分配与访问方式都可能改变计数。

五、回收、换页与分配器

页面分配器管理不同大小的物理页块，slab 类分配器在页面之上管理内核对象；它们不是应用虚拟地址分配器的同义词。NUMA 决定页面来自哪个节点，大页可能降低地址转换成本，也会增加连续内存需求和回收、拆分的复杂度。

内存紧张时，后台回收或分配路径中的直接回收会尝试释放可回收内容：干净的文件页通常可丢弃后重读，脏页需先写回；匿名页在允许且具备 swap 等条件时可换出。被固定、不可迁移或正在使用的页面会限制回收。回收不足可能导致分配失败或 OOM，而不是所有 mmap() 成功的空间都保证以后能写入。

RSS 下降可能来自回收或映射变化，并不直接说明应用释放了同样多的逻辑对象。共享页会影响 RSS 与 PSS 的解释；缓存占用内存也不自动意味着泄漏。

传统活跃／非活跃 LRU 用访问反馈估计冷热，MGLRU 则按访问时间组织多代页面，并结合页表访问位等信息选择回收对象。更细的冷热判断有扫描和同步成本；是否启用取决于内核配置与运行设置，不是只要升级到某个版本就必然生效。见 MGLRU 配置与工作集说明。

回收算法真正面对的是一个反馈问题：刚淘汰的文件页若马上又被读入，内核白做了回收和磁盘读取，工作集还可能反复抖动。访问位、页面所属代和重新访问的反馈用于改进冷热判断；但“找到冷页”只是开始，还要确认页能否解除映射、是否需要写回、有没有固定引用。选择回收对象与安全地释放对象是两步。

图中干净文件页有文件作为后备，丢弃后可以重读；脏文件页尚有未保存修改，必须安排写回并重新判断。匿名页没有原文件可重读，需要可用的换出路径。正因为“冷”与“可立即释放”不同，直接回收才可能让一次内存申请等待很久。

六、分配粒度、连续性与内存压力

Buddy 页面分配器按 order 管理连续页块：order 为 k 的请求需要 2k 个连续基页。对象分配器在这些页之上复用小对象，减少每个对象直接申请整页的浪费。总空闲内存充足，也可能因为缺少合适的连续块而无法满足较高 order 的请求。

kmalloc() 分配的区域在物理地址上连续；vmalloc() 提供连续的内核虚拟地址，后备物理页不必连续。两者都不能直接推出设备 DMA 地址：是否能 DMA、如何映射以及何时同步，要遵守 DMA API 和设备约束。内存分配指南按对象大小和上下文区分这些选择。

内存压力还可能来自某个 NUMA 节点或 cgroup，而不是全机总量。后台 kswapd 尽早回收，直接回收可能把延迟记到正在申请内存的线程上；页面规整通过迁移可移动页拼出连续空间，不能移动的固定页会限制效果。THP 可减少页表与 TLB 开销，但不保证每次大页分配都划算，参见 透明大页的工作方式。

七、只读观察与两级映射

在实验机查看 /proc/PID/maps 的范围与权限，再看 /proc/PID/smaps_rollup 的 RSS/PSS；/proc/meminfo 与 /proc/vmstat 反映系统层面的内存与回收活动。缺页、换页等计数是累积值，比较间隔差值；读取权限与可用字段可能随配置变化。

Guest 自己管理应用 VA 到 GPA 的页表，宿主管理 GPA 对应的后备内存，KVM 再维护 EPT 等第二级转换。Guest page fault 与 EPT violation 发生在不同层，Guest 分配了页也不意味着宿主早已建立所有映射。反过来，Guest 释放内存通常只是归还自己的分配器，宿主是否回收还取决于 balloon、空闲页报告和后备策略。

已有的 首次触碰实验可对照这些量；这里只提供观察方法，不把示意路径冒充本机测量结果。
