热升级：进程替换、资源保留与状态恢复

一、运行中的虚拟机怎样切换软件版本

更新磁盘上的 QEMU 程序后，已有虚拟机仍在旧进程中执行。要让它采用新版本，需要把运行状态交给新实例，并处理内存、设备和外部连接的连续性。这里的热升级允许短暂暂停客户机，目标是在不重新引导客户机的条件下完成软件切换。

基本做法是让旧实例停止执行客户机并保存状态，由新实例重建兼容的机器，再加载状态继续执行。保存和恢复越多内容，暂停通常越长。同一宿主上的进程替换可以进一步保留可共享的内存及资源，把工作集中在必须重建的对象和执行状态上。

QEMU、Libvirt 守护进程、vhost-user 后端和宿主内核具有不同的状态所有者，更新方法也不同。本文重点介绍 QEMU 同机进程替换；其他组件能否独立更新，需要检查自己的恢复或重连协议。

源码版本：QEMU 10.2.0。

二、先区分程序、运行状态和长期资源

磁盘上的 QEMU 文件提供程序代码，运行中的进程还有对象、线程、描述符和客户机状态。更换文件只影响以后启动的进程。要切换已有虚拟机，就要把它依赖的状态拆开：哪些可以直接保留，哪些需要按协议保存，哪些必须由新程序重新构建。

内容CPR-transfer 中的处理这样处理的原因
共享 RAM 的页面内容保留后备内存，传递描述符并重新映射同机进程可以引用同一资源，无需重传全部普通 RAM 页
CPU 寄存器、设备和队列状态按迁移协议保存并加载这些状态决定客户机下一步怎样执行
QEMU 对象、指针和执行线程新程序创建自己的对象与线程地址和内部布局可能改变，旧进程指针不能直接套用
KVM VM/vCPU 对象新进程创建并恢复相应状态保留 RAM 不代表旧执行环境也被直接接管
磁盘与外部后端维持内容一致，并按支持范围保留资源或重新连接客户机仍会继续之前的 I/O，外部状态不能被随意改动

普通保存恢复也能保持客户机的执行位置，但若暂停后把全部内存写出再读入，复制量会随 RAM 容量增长。同机升级利用共享资源缩小这部分工作；它仍需暂停和一致的状态交接，客户机没有重新引导并不意味着业务完全没有停顿。

三、保留资源、重建对象与交接执行权

同机 CPR-transfer 利用共享内存保留 RAM 内容。旧进程通过 Unix socket 传递已登记的文件描述符，新进程据此映射资源并建立自己的 QEMU、KVM 对象。随后旧端停止客户机，主迁移通道传送 CPU、设备与队列状态，新端加载成功后才恢复执行。

共享 RAM 必须在启动时采用兼容配置，附属 RAM 也要考虑。传递 fd 只增加资源引用，无法代替设备状态恢复或执行权切换。两端共享同一内存时，更需要避免同时放行客户机。

两条通道承担不同任务：CPR 通道先提供重建机器所需的资源引用，主迁移通道再提供可继续执行的 CPU 与设备状态。新端接收 CPR 信息发生在 monitor 就绪前，因此“新进程已经启动”也不能当作“可以发送任意 QMP 命令”。交接顺序由资源依赖关系决定。

四、一台 8 GiB 虚拟机的同机交接

假设原虚拟机采用共享 memfd RAM。旧 QEMU 的 fd 17 经 SCM_RIGHTS 传给新进程后可以成为 fd 23，两者仍引用同一内存后端。新进程的映射地址可以不同，客户机物理地址布局需保持兼容。

这省去了搬运 8 GiB 普通页数据，但仍要创建 vCPU、恢复寄存器和设备状态、处理后端与中断关系。停机时间覆盖旧端停止执行到新端恢复的间隔，此外还要观察接管后的业务尾延迟。目标一旦执行并修改共享内存，旧进程不能直接继续运行来回退。

假设暂停时客户机的下一条指令要读取 GPA 0x2000。新进程可以把该页映射到不同的宿主虚拟地址，但客户机仍应在相同 GPA 读到原来的内容；恢复的指令位置、队列索引及待处理中断也要与它一致。这个小例子解释了为什么资源共享和状态序列化缺一不可。

五、从保存重启到进程间资源交接

方式减少哪部分工作引入的条件与代价
保存状态后另起进程避免客户机重新引导，流程容易分阶段执行复制内存及新端准备可能占据较长暂停时间
cpr-reboot兼容配置下可保留共享 RAM，再启动新实例恢复两实例不并存，新实例的准备处于客户机停机阶段
cpr-transfer两实例短暂并存，先交接资源并准备新端需要共享 RAM、Unix 描述符通道及明确的执行权交接
cpr-exec替换程序并保留 PID 和支持保留的资源引用旧程序已被替换，恢复失败不能依赖原进程继续执行

这些模式共享迁移状态兼容要求：机器类型、CPU 能力、设备版本和资源标识都要对应。CPR-transfer 面向同一宿主，不能直接据此推导出跨机器迁移或通用宿主内核无停机升级。vhost 与字符设备等后端的连续保留也需要逐项检查支持情况。

这些方式利用迁移的状态协议，但优化方向从“尽量把数据搬到另一台宿主”变成“尽量保留同机可复用资源”。管理守护进程的更新又是另一种情况：若它能重连仍在运行的 QEMU，通常无需重建客户机执行环境，仍要处理进行中的管理任务和事件恢复。

六、升级收益与失败边界怎样验证

先列出所有设备和后端，确认状态兼容、资源保留与重连支持；再测量新端准备时间、客户机暂停、恢复后尾延迟及资源是否泄漏。只有 RAM 共享并不足以证明某种直通设备或外部后端也能顺利接管。

失败恢复要以执行权为界。源端仍保持有效状态、目标尚未接管时，可以评估取消并恢复源端；目标已经运行后，共享页和外部 I/O 可能变化，不能把旧进程当成未改变的快照。热升级的收益来自复用状态和资源，而可靠性取决于能否清楚界定每一步的所有权与回退条件。
