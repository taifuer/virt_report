一、启动要跨过哪些阶段

启动虚拟机涉及宿主资源准备、虚拟机器创建和客户机引导。Libvirt 把定义转为可运行的进程配置，QEMU 创建 CPU、内存与设备，KVM 提供硬件执行环境，客户机固件和操作系统随后完成自己的初始化。定位启动失败或耗时，需要先区分问题发生在哪一阶段。

冷启动首先要为客户机建立一套虚拟硬件，并把 CPU 和设备放到约定的复位状态。客户机随后像物理机一样，从固件开始识别硬件、寻找启动介质，再加载操作系统。管理层负责前一阶段的资源与执行条件，客户机软件负责后一阶段的引导。

本文以 x86、Q35、KVM 加速的冷启动为例。已有保存状态的恢复、迁入虚拟机的启动会复用其中部分步骤，但客户机的初始执行状态不同。

源码版本：QEMU 10.2.0、Libvirt 12.0.0。

二、先建立硬件，再让客户机自己引导

物理机上电后，CPU 从架构规定的复位入口执行固件。虚拟机也需要这个起点：QEMU 把固件映射到客户机地址空间，设置 CPU 复位状态，并提供固件能够枚举的总线、内存和设备。KVM 随后执行客户机指令；固件读磁盘时，设备模型和存储后端才把请求变成真实 I/O。

设想启动一台 2 vCPU、4 GiB RAM、virtio 磁盘的虚拟机。XML 中的“4 GiB”先变为 QEMU 的内存后端与客户机地址布局，再注册到 KVM；磁盘路径先变为块后端，再连接到客户机可见的控制器。只有这些关系成立，客户机才有条件执行引导程序。创建进程只是其中一步。

观察到的状态已经完成的工作还不能据此确认的事
虚拟机已定义管理层保存了配置宿主资源是否可用、QEMU 能否启动
机器已建立、处于暂停CPU、RAM、设备及管理连接已准备客户机是否已经执行固件
虚拟机运行中vCPU 获准执行内核、网络或应用是否就绪
业务健康检查通过指定服务已能处理测试请求其他服务及完整业务链路是否正常

三、从定义到客户机执行

1. Libvirt 准备宿主环境

启动请求先经过配置与权限检查，再准备磁盘、网络、设备和进程隔离。fork 与 exec 之间的握手让 cgroup、权限等约束在 QEMU 使用资源前生效。Libvirt 还加入 -S，让 QEMU 完成机器创建后暂不执行客户机代码。

这两个暂停点解决不同的竞态。进程启动握手用于避免 QEMU 在隔离措施生效前使用宿主资源；-S 用于避免客户机在管理层完成线程设置等操作前开始运行。若任一步失败，管理层要按已完成阶段回收资源，而不能留下被其他任务误认为可用的实例。

2. QEMU 建机，KVM 执行

QEMU 选择机器与 CPU 型号，建立 RAM、总线和设备，创建 KVM VM、vCPU 及宿主线程，完成复位。Libvirt 连接 QMP，查询线程并设置运行参数，再发送 cont。vCPU 开始进入 KVM_RUN，启动处理器从固件入口执行。

常见的磁盘启动路径中，固件选择启动设备并运行引导程序，引导程序加载内核与初始文件系统，内核初始化驱动和根文件系统，用户空间再启动服务。每个阶段都有独立的失败位置与完成条件，启动耗时也应沿这条链分别记录。

四、暂停启动一台虚拟机

对已定义、没有 managed save 的 demo 执行：

virsh start demo --paused
virsh domstate demo
virsh resume demo

第二步可以看到 paused，此时 QEMU 进程、机器与管理连接已经存在。resume 允许客户机开始执行；随后仍有固件枚举、内核引导和服务启动。应用可用时间需要客户机代理或业务健康检查确认，不能只看 PID、QMP 连接或 RUNNING 状态。

若 resume 成功后仍看不到登录提示，应先查看客户机控制台：停在固件菜单，检查启动介质和设备识别；内核找不到根文件系统，检查启动参数与驱动；已经登录但业务未就绪，再检查客户机网络和服务。沿阶段定位，可以避免把客户机软件问题都归为 QEMU 启动失败。

五、受控启动与兼容性的演进

QMP 的结构化命令与事件让管理程序可以协调启动阶段，而不必解析人工 monitor 输出。-S 提供执行前的暂停点；preconfig 则把部分配置操作提前到板级机器创建之前，两者不能互换。版本化机器类型让升级后的 QEMU 继续提供既有虚拟硬件接口，但 CPU 型号、固件和设备属性仍需匹配。

管理从人工命令转向结构化接口后，可以明确记录每阶段的输入与结果；机器类型的版本化进一步让相同虚拟硬件接口跨 QEMU 版本保留。代价是要维护更多状态和兼容属性。旧机器类型可以保留客户机预期，新设备和新属性则需要另行验证，升级程序并不会自动把运行中的机器转换为新型号。

六、启动优化应对应具体阶段

改进方向减少的等待需要接受的条件或代价
预先准备网络、存储与必要资源启动请求中的宿主准备时间提前占用资源，仍需处理失效与清理
裁减无用设备，调整客户机引导设备初始化、固件枚举和服务等待要验证驱动、引导方式和业务依赖
预分配 RAM运行初期的首次分配抖动可能延长机器准备阶段，并提前占用内存
从保存状态恢复重新执行固件、内核及部分初始化保存状态兼容性、恢复 I/O 和外部连接一致性

启动总耗时应拆为宿主准备、建机、固件、内核和应用就绪。优化其中一段后，要同时检查失败清理和服务可用时间。启动流程的核心是逐步建立运行条件，并在条件满足后放行下一阶段；这条顺序同样决定了故障定位的方法。
