一、如何把客户机报文交给物理网卡

virtio-net 已经解决客户机与虚拟设备之间的请求格式，但每个报文由谁处理、经过哪些线程、怎样到达物理网卡，还取决于后端。DPDK vhost-user 后端在独立用户态进程中消费客户机 virtqueue，将报文组织为 rte_mbuf，再交给网卡的轮询模式驱动（PMD）。QEMU 保留设备呈现和控制连接，通常不参与这条路径上的逐包处理。

本文跟踪一个 60 B 以太网帧 P1：客户机 TX 队列 → DPDK vhost → rte_mbuf → 物理网卡 TX 队列。分析采用 DPDK 24.11 的同步 split-ring 路径、单个队列对、普通复制模式，不启用分段和校验和卸载。客户机使用 modern virtio-net，12 B 网络头与帧分别放在两个只读描述符中。关键在于两次所有权交接：客户机缓冲区何时可以复用，以及交给 PMD 的 mbuf 何时可以释放。

源码版本：DPDK 24.11、QEMU 10.2.0。

二、整体路径：控制连接、共享队列与 PMD

DPDK 提供的是数据面基础设施，应用负责交换、路由、过滤或转发策略。vhost 库读写客户机共享队列，mempool 管理报文对象，ethdev 与 PMD 把统一的收发接口接到具体网卡。本文假设应用把 P1 转发到一个物理端口；同一后端也可以把报文送到另一台虚拟机，此时没有物理网卡 TX 这一步。

初始化需要建立哪些关系

  1. DPDK 应用初始化 EAL、mempool、网卡端口及 RX/TX 队列，安排数据线程与队列的对应关系。
  2. 通过 rte_vhost_driver_register() 注册 Unix socket 路径，设置支持的特性和设备生命周期回调，再启动控制连接。客户端或服务端角色只决定连接由谁建立。
  3. QEMU 传递共享 RAM 的文件描述符及内存区域信息；后端建立自己的虚拟地址映射。随后配置 virtqueue 大小、描述符和环地址、消费位置，以及 kick/call eventfd。
  4. 设备和队列就绪后，应用才将该队列加入数据线程的轮询集合。停止或断开时先退出这个集合，再处理在途访问与映射释放。

共享的物理页可以映射在 QEMU 和 DPDK 进程的不同虚拟地址。描述符中的设备地址需要经过已协商的内存映射或 IOTLB 转换，不能直接作为后端 C 指针使用。vhost-user 协议和DPDK 控制消息处理分别定义和实现这些关系。

轮询数据线程可以按协议请求客户机抑制 kick，直接检查 avail 索引；后端完成请求后仍须单独判断客户机是否需要中断。需要通知时触发 call eventfd，QEMU 配置的 KVM irqfd 路径可把它转换为客户机中断。eventfd 传递的是事件计数，描述符和帧内容仍保存在各自的内存缓冲区。split 完成通知判断

四、发送实例：从链 0 → 2 到物理出口

使用一个队列对时，virtio 队列 0 为客户机 RX，队列 1 为客户机 TX。应用调用 dequeue 从客户机取包，调用 enqueue 向客户机送包；函数命名以 vhost 接口为视角。以下状态从 TX 队列 1 的一次普通提交开始：

desc[0]: addr=0x1000, len=12, flags=NEXT, next=2   # virtio-net 头
desc[2]: addr=0x2000, len=60, flags=0              # P1，以太网帧
avail.ring[0] = 0; avail.idx = 1
last_avail_idx = 0; used.idx = 0

rte_vhost_dequeue_burst(vid, 1, pool, pkts, 32)
    → 返回 1，pkts[0] = M，M.pkt_len = 60
    → used.ring[0] = {id: 0, len: 0}; used.idx = 1

rte_eth_tx_burst(port, txq, pkts, 1)
    → 返回 1：M 交给 PMD
    → 返回 0：M 仍由应用负责

1. 消费与复制

rte_vhost_dequeue_burst() 检查设备、队列和协商状态，split 分支进入 virtio_dev_tx_split()。后者通过 acquire 读取 avail.idx，以与 last_avail_idx 的差计算新增请求数，再限定本批处理数量并从 mempool 分配 mbuf。

fill_vec_buf_split() 从 available 项取得头索引，验证链和缓冲区地址，整理客户机内存片段。desc_to_mbuf() 处理 virtio-net 头，将帧内容复制到 mbuf，并按协商的卸载语义填入元数据。本例 P1 为 60 B，因此 mbuf 中保存 60 B 帧；12 B virtio-net 头不作为以太网数据发送。描述符到 mbuf

2. 先归还客户机链，再交给物理网卡

vhost 先暂存 shadow used 项，在完成延后执行的复制操作后，批量写入共享 used ring，再以规定的内存顺序发布 used.idx。必要时触发完成通知。本例 used.len=0，表示后端没有向 TX 描述符缓冲区写入数据；完成的含义是客户机原缓冲区已用完。同步 split TX 路径

应用此时持有内容独立的 M，可以执行转发规则，然后调用 rte_eth_tx_burst()。返回 1 表示 PMD 接受 M 并把报文放入发送描述符；随后网卡 DMA 读取数据，PMD 在确认硬件完成后回收相应 mbuf。它不表示远端已收到报文。客户机 used 完成通常早于物理发送完成，两者由复制边界隔开。ethdev TX 接口与缓冲区回收

DPDK 的 vhost 示例在 drain_virtio_tx() 取包，交给 virtio_tx_route()，再由 do_drain_mbuf_table() 批量提交物理端口。真实交换机可以增加查表、隧道、限速等步骤，这些工作与 virtqueue 消费本身应分别计量。物理发送、客户机 TX 消费

五、完成与背压：哪一侧还持有报文

1. 发送环满时，used 完成无法撤销

假设本批从客户机取得 32 个 mbuf，而物理 TX 只接受 20 个。前 20 个的引用交给 PMD，后 12 个仍归应用。应用可以把剩余报文放入有界软件队列等待重试，也可以计数后丢弃并释放；不能把全部 32 个一起释放，也不能把未接受的 12 个遗忘。

普通同步 vhost 路径已经归还了这批客户机描述符，因此物理端口拥塞不会自动撤销客户机完成。若要把背压向前传播，需要应用控制下一批 dequeue 的速度或数量，并安排有界队列。增大缓冲只能吸收短期突发，不能修复持续的入口速率高于出口速率。

2. 反向收包有另一组所有权

物理网卡收到报文后，rte_eth_rx_burst() 把 mbuf 交给应用。应用对客户机 RX 队列调用 rte_vhost_enqueue_burst()，后端把数据复制到客户机预先提供的可写缓冲区，发布 used 项。同步调用返回后，应用仍负责释放自己的原 mbuf；enqueue 没有接管这个 mbuf 的生命周期。

客户机 RX 缓冲区不足时，enqueue 返回值会小于请求数，应用决定重试或丢弃。异步 DMA copy 使用独立 API 和完成检查，提交后不能按同步路径立即释放原数据，必须等相应复制完成。接收、重试与释放、异步接口约定

六、性能收益与成本怎样衡量

DPDK 数据线程通过持续轮询和 burst 批处理减少逐包唤醒、系统调用及部分共享同步开销。收益依赖流量规模、队列分配、NUMA 和网卡能力；在低负载或 CPU 资源紧张时，持续轮询的成本可能更突出。

设计选择解决的问题需要付出的代价或进一步检查
轮询与 burst减少频繁唤醒、摊薄逐包固定成本空闲仍消耗 CPU；只取“最多 32 个”不要求凑满，但应用主动等待凑批会增加延迟
普通 vhost 复制客户机可在物理发送前复用缓冲区，后端独立管理 mbuf消耗内存带宽和 CPU；本例不属于端到端零拷贝
队列与核心亲和性减少线程争用和跨核迁移需同时匹配客户机队列、后端线程、网卡队列及 NUMA 内存；队列越多并不一定越快
多段 mbuf 与卸载承载大报文，利用网卡分段或校验和能力各层必须一致协商；PMD 的段数、长度和卸载限制可能要求额外整理
独立进程与共享 RAM设备控制与网络转发可分别调度和维护后端拥有客户机内存访问权限；连接恢复、内存变化及迁移时的队列状态需协调

检查瓶颈时，先记录客户机 avail 积压、vhost 每批取包数、mbuf 分配失败、PMD 接受数和软件队列积压，再看 CPU cycles/packet、吞吐、丢包与尾延迟。在相同包长和卸载条件下比较 QEMU TAP、内核 vhost-net 与 DPDK，才能说明某一步处理位置的改变带来了什么收益。

七、从用户态后端到队列与复制优化

把 virtio 后端移到独立用户态进程，使交换机可以统一调度多个虚拟机和物理端口，代价是必须管理共享内存、队列状态与进程生命周期。DPDK 16.07 加入 vhost-user 客户端模式，重连能力进一步减少了固定启动顺序的约束；重连后仍需恢复一致的特性和队列状态，socket 恢复不等于在途报文自动恢复。vhost-user 连接模式

split 到 packed 的队列演进把发布与完成标记集中到一张描述符环，改善元数据访问局部性，同时引入 wrap counter 和不同的所有权判断。后端与客户机必须协商使用同一种格式；本文的 desc → avail → used 三个共享区域不能直接套到 packed 上。split / packed 数据路径选择

当复制成为瓶颈，可以考虑 DMA copy 卸载。复制仍然存在，只是执行者从 CPU 转为 DMA 设备；提交、完成轮询、缓冲区存活和 DMA 通道资源变得更重要。DPDK 18.11 已提供 vDPA 示例，利用硬件实现兼容 virtio 的数据面，减少专门的 vhost 轮询工作；可迁移状态、特性组合和硬件支持随之成为约束。18.11 的 vDPA 示例

这些演进分别针对进程调度、元数据访问、内存复制和数据面执行位置。先用 P1 的路径确认时间和 CPU 花在哪里，再选择改变哪一个环节。块设备的 SPDK vhost 后端采用不同的请求格式和存储完成语义，可结合SPDK vhost-blk 的请求与完成路径对照。
