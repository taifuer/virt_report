一、为一台虚拟机建立内核执行环境

用户态 VMM 通过 KVM API 建立虚拟机、注册内存、配置中断控制器并创建 vCPU。本文先解释这些对象的依赖，再用一个最小 x86 程序完成整条调用链：创建 2 MiB RAM 和一个 vCPU，让客户机写入数值 42，通过端口 I/O 返回用户态，最后释放资源。

宿主的 kvm 与 kvm_intel / kvm_amd 模块加载、硬件虚拟化能力可用后，用户态通过 /dev/kvm 为每台虚拟机建立独立对象。创建流程从这个接口开始。

源码版本：QEMU 10.2.0、Linux 6.18。

二、系统 fd、VM fd 与 vCPU fd

open /dev/kvm → 系统 fd
  ├─ KVM_GET_API_VERSION / KVM_CHECK_EXTENSION
  ├─ KVM_GET_VCPU_MMAP_SIZE
  └─ KVM_CREATE_VM → VM fd
       ├─ 注册内存槽、创建 irqchip、配置路由
       ├─ KVM_CREATE_VCPU → vCPU 0 fd → mmap kvm_run
       └─ KVM_CREATE_VCPU → vCPU 1 fd → mmap kvm_run

系统 fd 用于查询 KVM 能力并创建 VM；VM fd 用于操作整机资源；vCPU fd 用于设置寄存器和执行某个虚拟处理器。内核分别维护 struct kvm 和 struct kvm_vcpu。同一 VM 的 vCPU 共享内存布局，各自拥有体系结构状态、LAPIC 状态与执行控制。

用户态先验证 API 版本，再查询所需的 KVM_CAP_*。API 版本号并不枚举全部功能，部分能力还需要通过 KVM_ENABLE_CAP 显式启用。调用返回值必须逐项检查，不能在某项初始化失败后继续运行半成品机器。

三、内存：分配后备，再登记 GPA 范围

QEMU 先用匿名映射或文件映射取得 RAM 后备，构建客户机物理地址布局，再把可供 KVM 直接访问的区域登记成 memslot。KVM_SET_USER_MEMORY_REGION 的主要字段是槽号、起始 GPA、长度和 userspace_addr；新扩展接口还有额外的内存后备能力，本例使用普通用户态 RAM。

字段或对象示例含义
slot0该 VM 内用于更新或删除这段区域的标识
guest_phys_addr0x00000000客户机看到的这段 RAM 的起点
memory_size0x200000（2 MiB）后文最小实例使用的连续 RAM 长度
userspace_addrHVA_base用户态 VMM 中对应后备映射的起点

访问 GPA 0x2000 时，KVM 可由槽定位到 HVA_base + 0x2000，再取得后备页建立 EPT/NPT。注册 memslot 不是一次性分配全部物理页，也不表示二级页表已经全部建好。实际 PC 还包含 RAM 空洞、ROM 与 MMIO，通常需要多个区域，不能把上表示例套成完整 Q35 地址布局。

普通设备模拟的 MMIO 区域由 QEMU 设备回调处理，通常不登记为普通 RAM 槽。未命中 RAM 的访问由 KVM 判定后可返回用户态模拟；受支持的直通映射则可能直接映射设备页。内存所有权、访问属性和生命周期必须与设备类型一致。

四、中断：创建控制器，再连接事件源

x86 的 KVM_CREATE_IRQCHIP 创建内核 PIC、I/O APIC，并使随后创建的 vCPU 拥有内核 LAPIC；这个调用须在创建 vCPU 之前完成。split irqchip 是另一种配置：传统引脚控制器由 QEMU 提供，LAPIC 仍在 KVM。这里固定完整内核 irqchip 路径。

控制器准备好后，VMM 按设备配置建立路由：引脚中断可通过 KVM_IRQ_LINE 改变电平；MSI 消息可用 KVM_SIGNAL_MSI 提交；独立后端可经 KVM_SET_GSI_ROUTING 与 KVM_IRQFD 将 eventfd 接到目标路由。创建 irqchip 只准备了控制器，设备路由和客户机驱动配置还会在后续阶段完善。

PC 还需要 PIT、RTC、HPET 或 LAPIC timer 等计时设施，具体模型由机器类型和配置决定。中断路由的目标是虚拟 APIC ID；目标 vCPU 线程实际运行在哪个宿主 CPU，由宿主调度器决定。

五、vCPU：对象、线程与启动状态

KVM_CREATE_VCPU 返回 vCPU fd 并建立内核对象。宿主线程由 QEMU 创建，创建 vCPU 对象本身不会让 KVM 自动创建一个运行客户机的独立内核线程。常见 QEMU/KVM 配置中，每个 vCPU 对应一个 QEMU 线程，由该线程调用 KVM_RUN。

用户态用 KVM_GET_VCPU_MMAP_SIZE 查询共享区大小，再 mmap vCPU fd 得到 struct kvm_run。该区交换退出原因、MMIO 或 PIO 数据等信息；完整寄存器状态使用专门的 vCPU ioctl 维护，kvm_run 不是全部寄存器的共享副本。

初始配置包括 CPUID、通用与特殊寄存器、MSR、FPU/扩展状态和 MP 状态，具体接口随能力与机器配置选择。典型接口有 KVM_SET_CPUID2、KVM_SET_REGS、KVM_SET_SREGS、KVM_SET_MSRS 和 KVM_SET_MP_STATE。BSP 从配置的复位入口执行，AP 按启动状态等待 INIT/SIPI 等启动过程。

QEMU 可以较早创建 vCPU 线程，让它完成初始化握手后保持 stopped；主线程随后继续 RAM、固件和外设准备。初始化的约束是所需依赖在使用前就绪，不是每台机器都必须按“全部内存 → 全部设备 → 全部 vCPU”的固定顺序创建。

六、从整机复位到第一次执行

用户态将固件内容放进可取指的客户机地址范围，复位设备和 CPU，向 KVM 同步启动状态。放行后，vCPU 线程调用 ioctl(vcpu_fd, KVM_RUN)，KVM 加载体系结构状态并进入客户机，硬件从配置的指令地址开始执行。

物理 CPU 遇到受拦截操作可能先退出到 KVM。KVM 能处理的事件在内核完成，需要用户态设备模拟的访问才通过 KVM_RUN 返回，并在 kvm_run 中注明原因。用户态完成模拟后再次调用 KVM_RUN，客户机继续执行。这个循环承担运行期处理，创建流程为它准备对象与资源。

首次进入 Guest 只意味着 CPU 已开始执行，操作系统仍要经历固件、引导、驱动和服务初始化。内存槽登记成功、vCPU 创建成功与业务启动成功，应分别检查。

七、最小实例：创建并执行一个 vCPU

下面的程序在 x86 Linux 上直接使用 KVM API，只创建自己的临时虚拟机。它不接磁盘或网络，也不加载固件与操作系统；Guest 代码直接放在 GPA 0x1000，以 16 位实模式运行。宿主需提供可读写的 /dev/kvm 和示例检查的 KVM 能力。

1. 先确定地址与执行结果

配置值作用
RAM 槽 0GPA [0, 0x200000)对应用户态 mmap 得到的 2 MiB；Guest 写入 GPA 0x2000 后，宿主读取 ram[0x2000]。
CS 与 RIPCS.base=0，RIP=0x1000首次取指直接到示例代码，不经过 BIOS 复位入口。
DS 与数据地址DS.base=0，偏移 0x2000实模式下直接访问该槽中的数据，Guest 尚未启用分页。
端口 0xe9由示例用户态程序处理Guest 执行 OUT 后得到 KVM_EXIT_IO；该写入不会发往宿主的真实 I/O 端口。
irqchip先于 vCPU 创建建立内核 PIC、I/O APIC 和后续的 LAPIC；本例没有中断源，RFLAGS.IF 保持清零。

创建 vCPU 0 后，程序读取初始特殊寄存器，仅修改本例需要的段基址和通用寄存器。Guest 不执行 CPUID、浮点或操作系统启动代码，因此没有展开完整机器的 CPUID/MSR 配置。QEMU 的 CPU 模型和固件启动仍需前文列出的相应初始化。

2. 完整程序

将代码保存为 kvm-minimal.c。CHECK 会检查每次系统调用，失败时统一进入清理路径；使用负值 fd 与 MAP_FAILED 标记尚未获得的资源。

#define _GNU_SOURCE
#include <errno.h>
#include <fcntl.h>
#include <linux/kvm.h>
#include <stdint.h>
#include <stdio.h>
#include <string.h>
#include <sys/ioctl.h>
#include <sys/mman.h>
#include <unistd.h>

#if !defined(__x86_64__) && !defined(__i386__)
#error "This example requires an x86 Linux host"
#endif

int main(void)
{
    const size_t ram_size = 2 * 1024 * 1024;
    int kvm = -1, vm = -1, vcpu = -1, result = 1;
    int run_size = 0, rc;
    unsigned char *ram = MAP_FAILED;
    struct kvm_run *run = MAP_FAILED;
    const char *operation = "open /dev/kvm";

#define CHECK(call) do { \
    operation = #call; \
    if ((call) < 0) goto fail; \
} while (0)

    CHECK(kvm = open("/dev/kvm", O_RDWR | O_CLOEXEC));
    CHECK(rc = ioctl(kvm, KVM_GET_API_VERSION, 0));
    if (rc != KVM_API_VERSION) {
        fprintf(stderr, "Unsupported KVM API: %d\n", rc);
        goto cleanup;
    }
    const int capabilities[] = {
        KVM_CAP_USER_MEMORY, KVM_CAP_IRQCHIP,
        KVM_CAP_SET_TSS_ADDR, KVM_CAP_IMMEDIATE_EXIT
    };
    for (size_t i = 0; i < sizeof(capabilities) / sizeof(capabilities[0]); i++) {
        CHECK(rc = ioctl(kvm, KVM_CHECK_EXTENSION, capabilities[i]));
        if (rc == 0) {
            fprintf(stderr, "Required KVM capability missing: %d\n", capabilities[i]);
            goto cleanup;
        }
    }
    CHECK(vm = ioctl(kvm, KVM_CREATE_VM, 0));
    /* Reserve three GPA pages for Intel's real-mode TSS, outside guest RAM. */
    CHECK(ioctl(vm, KVM_SET_TSS_ADDR, 0xfffbd000UL));
    CHECK(ioctl(vm, KVM_CREATE_IRQCHIP, 0));

    operation = "mmap guest RAM";
    ram = mmap(NULL, ram_size, PROT_READ | PROT_WRITE,
               MAP_PRIVATE | MAP_ANONYMOUS, -1, 0);
    if (ram == MAP_FAILED) goto fail;
    struct kvm_userspace_memory_region region = {
        .slot = 0, .guest_phys_addr = 0, .memory_size = ram_size,
        .userspace_addr = (uintptr_t)ram
    };
    CHECK(ioctl(vm, KVM_SET_USER_MEMORY_REGION, &region));
    /* 16-bit real mode: store 42 at 0x2000, then OUT 42 to port 0xe9. */
    const unsigned char guest[] = {
        0xc6, 0x06, 0x00, 0x20, 0x2a, /* mov byte [0x2000], 42 */
        0xb0, 0x2a,                   /* mov al, 42 */
        0xe6, 0xe9,                   /* out 0xe9, al */
        0xf4                          /* hlt: not executed in this example */
    };
    memcpy(ram + 0x1000, guest, sizeof(guest));

    CHECK(vcpu = ioctl(vm, KVM_CREATE_VCPU, 0));
    CHECK(run_size = ioctl(kvm, KVM_GET_VCPU_MMAP_SIZE, 0));
    if ((size_t)run_size < sizeof(*run)) {
        fprintf(stderr, "KVM run mapping is too small\n");
        goto cleanup;
    }
    operation = "mmap kvm_run";
    run = mmap(NULL, (size_t)run_size, PROT_READ | PROT_WRITE,
               MAP_SHARED, vcpu, 0);
    if (run == MAP_FAILED) goto fail;
    struct kvm_sregs sregs;
    CHECK(ioctl(vcpu, KVM_GET_SREGS, &sregs));
    sregs.cs.base = sregs.cs.selector = 0;
    sregs.ds.base = sregs.ds.selector = 0;
    struct kvm_regs regs = { .rip = 0x1000, .rsp = 0x8000, .rflags = 2 };
    CHECK(ioctl(vcpu, KVM_SET_SREGS, &sregs));
    CHECK(ioctl(vcpu, KVM_SET_REGS, &regs));
    struct kvm_mp_state mp = { .mp_state = KVM_MP_STATE_RUNNABLE };
    CHECK(ioctl(vcpu, KVM_SET_MP_STATE, &mp));

    operation = "KVM_RUN";
    do {
        rc = ioctl(vcpu, KVM_RUN, 0);
    } while (rc < 0 && errno == EINTR);
    if (rc < 0) goto fail;
    if (run->exit_reason != KVM_EXIT_IO ||
        run->io.direction != KVM_EXIT_IO_OUT || run->io.port != 0xe9 ||
        run->io.size != 1 || run->io.count != 1 ||
        run->io.data_offset >= (uint64_t)run_size) {
        fprintf(stderr, "Unexpected KVM exit: %u\n", run->exit_reason);
        goto cleanup;
    }
    unsigned char value = *((unsigned char *)run + run->io.data_offset);
    if (value != 42 || ram[0x2000] != 42) {
        fprintf(stderr, "Guest result mismatch\n");
        goto cleanup;
    }
    /* Complete the pending OUT, but do not execute the following HLT. */
    run->immediate_exit = 1;
    rc = ioctl(vcpu, KVM_RUN, 0);
    if (rc != -1 || errno != EINTR) {
        fprintf(stderr, "Expected EINTR after completing the OUT\n");
        goto cleanup;
    }
    CHECK(ioctl(vcpu, KVM_GET_REGS, &regs));
    if (regs.rip != 0x1009) {
        fprintf(stderr, "Unexpected RIP: 0x%llx\n", (unsigned long long)regs.rip);
        goto cleanup;
    }
    printf("RAM[0x2000]=42, OUT(0xe9)=42, RIP=0x%llx\n",
           (unsigned long long)regs.rip);
    result = 0;
    goto cleanup;

fail:
    fprintf(stderr, "%s: %s\n", operation, strerror(errno));
cleanup:
    if (run != MAP_FAILED) munmap(run, (size_t)run_size);
    if (vcpu >= 0) close(vcpu);
    if (vm >= 0) close(vm);
    if (ram != MAP_FAILED) munmap(ram, ram_size);
    if (kvm >= 0) close(kvm);
    return result;
}

3. 编译、运行与结果核对

cc -std=c11 -Wall -Wextra -Werror -O2 kvm-minimal.c -o kvm-minimal
timeout 5s ./kvm-minimal

需要 C 编译器与 Linux 用户态开发头文件。具备相应 KVM 环境时，预期输出为：

RAM[0x2000]=42, OUT(0xe9)=42, RIP=0x1009

这三个值分别确认共享 RAM 写入、用户态收到端口请求，以及该指令已经完成。第一次 KVM_RUN 返回 I/O 请求时，内核还保留待完成操作；程序设置 immediate_exit=1 后重新进入，完成 OUT，再以 EINTR 返回，不执行末尾的 HLT。启用内核 irqchip 后，HLT 可能让 vCPU 阻塞，所以本例用 I/O 请求作为结束信号。

验证范围：此代码接受编译和模拟系统调用测试；当前检查环境没有 /dev/kvm，上述输出是预期值，尚未在真实 KVM 上验证。程序失败时会打印具体调用；权限不足应先核对设备访问权限，缺少能力则使用满足条件的测试宿主。

八、失败清理与对象生命周期

创建失败时，VMM 停止使用尚未完成的实例，按已获得的资源逆向清理：停止执行和异步设备活动，解除通知绑定，释放 vCPU 共享映射与 fd，释放 VM 及内存后备引用。正常退出也要先保证设备不会再 DMA 到准备释放的内存。

KVM 对象的存活依赖引用，关闭一个重复的 fd 不一定释放对象。KVM API 对 ioctl 调用进程和线程也有约束，不能把 fd 当作任意跨进程移交虚拟机状态的协议。QEMU 的常规迁移会在目标重新建立相应对象。

失败位置本例已获得的资源清理顺序
VM 创建前系统 fd关闭系统 fd。
内存槽注册或 vCPU 创建失败VM fd，可能已有 RAM 映射关闭 VM，再解除 RAM 映射，最后关闭系统 fd。
寄存器设置或运行失败VM、RAM、vCPU fd 与 kvm_run 映射解除 kvm_run，关闭 vCPU 与 VM，再解除 RAM，关闭系统 fd。

本例没有后台工作线程、异步 I/O 或设备 DMA，返回用户态后即可按上述顺序销毁。完整 VMM 则要先停止相关线程和设备活动，才能释放它们仍可能访问的内存。
