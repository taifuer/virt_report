一、为一台虚拟机建立内核执行环境

QEMU 创建机器模型时，会调用 KVM 建立虚拟机容器、注册客户机内存、准备中断控制器并创建 vCPU。KVM 提供受硬件保护的执行环境；固件、磁盘、网卡与机器布局由用户态 VMM 组织。本文以 x86、普通共享 RAM、内核 irqchip 为例，跟踪这些对象如何在第一次 KVM_RUN 前准备好。

宿主的 kvm 与 kvm_intel / kvm_amd 模块加载、硬件虚拟化能力可用后，用户态通过 /dev/kvm 为每台虚拟机建立独立对象。创建流程从这个接口开始。

源码版本：QEMU 10.2.0、Linux 6.18。

二、系统 fd、VM fd 与 vCPU fd

open /dev/kvm → 系统 fd
  ├─ KVM_GET_API_VERSION / KVM_CHECK_EXTENSION
  ├─ KVM_GET_VCPU_MMAP_SIZE
  └─ KVM_CREATE_VM → VM fd
       ├─ 注册内存槽、创建 irqchip、配置路由
       ├─ KVM_CREATE_VCPU → vCPU 0 fd → mmap kvm_run
       └─ KVM_CREATE_VCPU → vCPU 1 fd → mmap kvm_run

系统 fd 用于查询 KVM 能力并创建 VM；VM fd 用于操作整机资源；vCPU fd 用于设置寄存器和执行某个虚拟处理器。内核分别维护 struct kvm 和 struct kvm_vcpu。同一 VM 的 vCPU 共享内存布局，各自拥有体系结构状态、LAPIC 状态与执行控制。

用户态先验证 API 版本，再查询所需的 KVM_CAP_*。API 版本号并不枚举全部功能，部分能力还需要通过 KVM_ENABLE_CAP 显式启用。调用返回值必须逐项检查，不能在某项初始化失败后继续运行半成品机器。

三、内存：分配后备，再登记 GPA 范围

QEMU 先用匿名映射或文件映射取得 RAM 后备，构建客户机物理地址布局，再把可供 KVM 直接访问的区域登记成 memslot。KVM_SET_USER_MEMORY_REGION 的主要字段是槽号、起始 GPA、长度和 userspace_addr；新扩展接口还有额外的内存后备能力，本例使用普通用户态 RAM。

字段或对象示例含义
slot0该 VM 内用于更新或删除这段区域的标识
guest_phys_addr0x00000000客户机看到的这段 RAM 的起点
memory_size0x40000000（1 GiB）本例一段连续 RAM 的长度
userspace_addrHVA_baseQEMU 进程内对应后备映射的起点

访问 GPA 0x2000 时，KVM 可由槽定位到 HVA_base + 0x2000，再取得后备页建立 EPT/NPT。注册 memslot 不是一次性分配全部物理页，也不表示二级页表已经全部建好。实际 PC 还包含 RAM 空洞、ROM 与 MMIO，通常需要多个区域，不能把上表示例套成完整 Q35 地址布局。

普通设备模拟的 MMIO 区域由 QEMU 设备回调处理，通常不登记为普通 RAM 槽。未命中 RAM 的访问由 KVM 判定后可返回用户态模拟；受支持的直通映射则可能直接映射设备页。内存所有权、访问属性和生命周期必须与设备类型一致。

四、中断：创建控制器，再连接事件源

x86 的 KVM_CREATE_IRQCHIP 创建内核 PIC、I/O APIC，并使随后创建的 vCPU 拥有内核 LAPIC；这个调用须在创建 vCPU 之前完成。split irqchip 是另一种配置：传统引脚控制器由 QEMU 提供，LAPIC 仍在 KVM。这里固定完整内核 irqchip 路径。

控制器准备好后，VMM 按设备配置建立路由：引脚中断可通过 KVM_IRQ_LINE 改变电平；MSI 消息可用 KVM_SIGNAL_MSI 提交；独立后端可经 KVM_SET_GSI_ROUTING 与 KVM_IRQFD 将 eventfd 接到目标路由。创建 irqchip 只准备了控制器，设备路由和客户机驱动配置还会在后续阶段完善。

PC 还需要 PIT、RTC、HPET 或 LAPIC timer 等计时设施，具体模型由机器类型和配置决定。中断路由的目标是虚拟 APIC ID；目标 vCPU 线程实际运行在哪个宿主 CPU，由宿主调度器决定。

五、vCPU：对象、线程与启动状态

KVM_CREATE_VCPU 返回 vCPU fd 并建立内核对象。宿主线程由 QEMU 创建，创建 vCPU 对象本身不会让 KVM 自动创建一个运行客户机的独立内核线程。常见 QEMU/KVM 配置中，每个 vCPU 对应一个 QEMU 线程，由该线程调用 KVM_RUN。

用户态用 KVM_GET_VCPU_MMAP_SIZE 查询共享区大小，再 mmap vCPU fd 得到 struct kvm_run。该区交换退出原因、MMIO 或 PIO 数据等信息；完整寄存器状态使用专门的 vCPU ioctl 维护，kvm_run 不是全部寄存器的共享副本。

初始配置包括 CPUID、通用与特殊寄存器、MSR、FPU/扩展状态和 MP 状态，具体接口随能力与机器配置选择。典型接口有 KVM_SET_CPUID2、KVM_SET_REGS、KVM_SET_SREGS、KVM_SET_MSRS 和 KVM_SET_MP_STATE。BSP 从配置的复位入口执行，AP 按启动状态等待 INIT/SIPI 等启动过程。

QEMU 可以较早创建 vCPU 线程，让它完成初始化握手后保持 stopped；主线程随后继续 RAM、固件和外设准备。初始化的约束是所需依赖在使用前就绪，不是每台机器都必须按“全部内存 → 全部设备 → 全部 vCPU”的固定顺序创建。

六、从整机复位到第一次执行

用户态将固件内容放进可取指的客户机地址范围，复位设备和 CPU，向 KVM 同步启动状态。放行后，vCPU 线程调用 ioctl(vcpu_fd, KVM_RUN)，KVM 加载体系结构状态并进入客户机，硬件从配置的指令地址开始执行。

物理 CPU 遇到受拦截操作可能先退出到 KVM。KVM 能处理的事件在内核完成，需要用户态设备模拟的访问才通过 KVM_RUN 返回，并在 kvm_run 中注明原因。用户态完成模拟后再次调用 KVM_RUN，客户机继续执行。这个循环承担运行期处理，创建流程为它准备对象与资源。

首次进入 Guest 只意味着 CPU 已开始执行，操作系统仍要经历固件、引导、驱动和服务初始化。内存槽登记成功、vCPU 创建成功与业务启动成功，应分别检查。

七、失败清理与对象生命周期

创建失败时，VMM 停止使用尚未完成的实例，按已获得的资源逆向清理：停止执行和异步设备活动，解除通知绑定，释放 vCPU 共享映射与 fd，释放 VM 及内存后备引用。正常退出也要先保证设备不会再 DMA 到准备释放的内存。

KVM 对象的存活依赖引用，关闭一个重复的 fd 不一定释放对象。KVM API 对 ioctl 调用进程和线程也有约束，不能把 fd 当作任意跨进程移交虚拟机状态的协议。QEMU 的常规迁移会在目标重新建立相应对象。
