产业周报

往期报告
2026-11-16 至 2026-11-22

Cloud Hypervisor 55 更新了直通设备之间的 DMA 映射方式。Azure 开放直接虚拟化的私有预览申请，并将 Guest RDMA 公开预览扩展到所有提供相应虚机规格的区域。AWS 为 EC2 加速实例增加了硬件性能状态检查。

  1. Cloud Hypervisor 55 发布：VFIO 设备间 DMA 支持 dma-buf [1]

    2026-11-19

    两个直通设备进行点对点 DMA 时，Cloud Hypervisor 可以通过 VFIO 将设备可共享的 BAR 内存区域导出为 dma-buf，再由 iommufd 将它映射到另一台设备的 DMA 地址空间。宿主内核不支持这条路径时，仍使用原有的映射方式。

    热迁移的 CPU 兼容性检查也加入了 AMD 特有的 CPUID 项。源端与目标端在这些能力上不兼容时，以前能通过检查的迁移请求现在会被拒绝。

  2. Azure 直接虚拟化开放私有预览申请 [2]

    2026-11-18

    Direct Virtualization 让 Azure 虚机内的沙箱直接由底层 Hypervisor 运行，服务仍可选择沙箱操作系统，省去在虚机内再运行一层 KVM 的开销。微软在相同宿主配置上测试 Redis：基线密度下两者吞吐接近，负载密度增至四倍时，直接虚拟化比嵌套 KVM 高约 32%。

    Red Hat 与微软正为 OpenShift Virtualization 适配这一执行后端，合作涉及 KubeVirt、libvirt、QEMU 和 Linux 内核。 [3]

  3. Azure Boost 扩大 Guest RDMA 公开预览范围 [4]

    2026-11-18

    公开预览现覆盖所有提供相应机型的 Azure 区域，支持部分第五代 Intel Xeon 和 AMD EPYC 虚机。客户机应用通过 RDMA verbs 收发数据，Azure Boost 网卡负责传输处理，RDMA 数据绕过客户机的常规网络栈。

    网卡配置使用 2026-07-01 版 API，同时开启加速网络（enableAcceleratedNetworking）和 enableGuestRdma。

  4. Azure 的 AMD 机密虚机开始预览 Secure AVIC [5]

    2026-11-17

    采用第五代 AMD EPYC 的 Azure v7 机密虚机引入 Secure AVIC，由硬件保护 SEV-SNP 客户机的中断注入，并加快客户机对本地 APIC 的访问。微软在美国中南部和英国南部提供受限预览。

  5. 微软演示 Intel TDX 机密虚机与 Azure Boost 设备之间的直接 DMA [6]

    2026-11-18

    微软在 Ignite 上展示了支持 TDISP 的 Boost 设备如何接入机密虚机：平台验证设备身份，建立安全通道，并把设备配置和访问策略绑定到虚机的启动度量。经验证的设备可以直接访问受保护内存，省去通过共享缓冲区中转数据的一次复制。

  6. Azure Red Hat OpenShift 发布 BGP 连接器，保留虚机源 IP [7]

    2026-11-19

    连接器让集群内的路由节点通过 BGP 向 Azure Route Server 宣告虚机所在网段。虚机对外通信时保留自己的源 IP，外部防火墙可以区分同一工作节点上的不同虚机。

    Red Hat 的部署文档使用 ARO Standard、OpenShift 4.22 和服务主体认证，通过两个路由节点验证了虚机与集群外网络的双向连通。 [8]

  7. EC2 为加速实例增加硬件性能状态检查 [9]

    2026-11-19

    EC2 可在实例仍在线时报告影响性能的底层硬件问题。例如，GPU 出现可修复的显存行故障时，检查结果可以指出重启即可完成显存行重映射，无需更换实例。

    状态检查本身免费。另行启用详细监控后，可按一分钟粒度取得 GPU 指标、按十秒粒度观察 CPU 利用率；这些指标按 CloudWatch 详细监控计费。
