  1. QEMU 配置设备；内核后端通过 ioctl，外部后端通过 Unix socket 获得内存、队列及通知信息。
  2. 客户机发布 available 项，按需 kick；选定消费者读取同一份描述符和报文。
  3. QEMU 或 vhost-net 交给 TAP；外部后端使用自身的网络出口。
  4. 后端回写 used，按条件通知客户机，驱动随后回收缓冲区。

启用 JavaScript 可切换处理位置，并逐步观察初始化与发送过程。

本例采用 eventfd 通知，假定 kick 和完成通知均需要发送，后端发送成功；每步表示逻辑阶段。外部后端以协议职责表示，不限定其线程或网络实现。切换后端会重置过程。
