场景与边界

跟踪一笔 GPU 作业 G1，从 Guest 用户态提交命令，到硬件搬运数据、驱动确认完成，最后应用使用结果。直通场景分别展示上传与读回；mdev 场景展示一个受宿主管理的虚拟 GPU 提交。这里的“读写”是缓冲区之间的数据传输，不是把 GPU 当成磁盘调用 read() 或 write()。

VFIO PCI 路径固定 AMD Vega10 / SDMA 4.0 与公开 AMDGPU 驱动，观察 Guest RAM 和 VRAM 之间的 4 KiB 复制。mdev 路径固定旧代 Skylake 的 Intel GVT-g / i915 execlists，观察共享系统内存中的 BLT 复制；它不是通用 NVIDIA vGPU 流程，也不表示当前所有 Intel GPU 都支持该实现。设备初始化、BO 分配和基础映射已完成。

演示区分 Guest、KVM、QEMU、Host kernel 和物理 GPU。KVM 本身运行在宿主内核；这里把它与 VFIO、i915/GVT-g 分开，是为了区分 vCPU / 中断虚拟化与设备管理职责，不表示五个组件必须依次转发每条命令。

AMDGPU 的 CS 提交路径先核验上下文、对象和 GPU VM，再把作业交给 DRM 调度器。调度回调组织 IB、fence 与 ring 发布；SDMA 硬件随后执行。等待接口既有 ioctl 返回值，也有输出状态，不能把“调用成功”和“作业完成”混为一谈。

地址转换与宿主参与

整卡直通时，宿主这块 PCI 设备绑定的是 vfio-pci，而非 amdgpu；真正接收应用 CS ioctl、组织 GPU 作业的是 Guest 内的 AMDGPU 驱动。宿主 VFIO 管理设备资源、DMA 隔离和中断接口，QEMU 预先配置虚拟设备、BAR 与中断路由，KVM 维护 vCPU 的二级地址转换并递送虚拟中断。它们不代替 Guest 驱动逐条解释或转发 GPU 命令。参见 Linux VFIO 文档。

本例先在 Guest RAM / GTT 写好 IB 与 SDMA ring，再由 Guest CPU 向可 mmap 的 doorbell BAR 写入新写指针。这个 CPU 访问沿 Guest VA → GPA → 已建立的 EPT → 物理 BAR，直接让 GPU 看见门铃；门铃不是 4 KiB 数据载荷，也不需要每次调用宿主 VFIO 或返回 QEMU。GPU 随后自己读取 ring 和 IB：访问系统内存经过 GPU 地址转换与宿主 IOMMU 的预建映射，访问本地 VRAM 则不等于一次系统内存 DMA。SDMA ring 在该驱动中分配于 GTT，本例用户 IB1 也选择 GTT；不是所有 GPU 命令缓冲区都必须放在系统内存。

数据复制及 fence 写回完成后，物理 MSI 由宿主 VFIO 触发 eventfd，KVM irqfd 把向量路由到目标 vLAPIC；目标 vCPU 在允许时注入，Guest AMDGPU 才处理完成并唤醒应用。演示把 pending 与实际注入分开。未直接映射、需要捕获或特殊处理的 BAR 区域仍可能进入 KVM / QEMU 的 VFIO region 回调，不能用“直通”推导全部寄存器访问都不退出。

GVT-g 不沿用上述直通快路径：宿主物理 GPU 由 i915/GVT-g 管理。本例 ELSP 写先由 KVM 捕获，经 QEMU 的 VFIO region 进入宿主 GVT-g，再审核 workload、建立影子上下文并调度真实引擎；完成后由 GVT-g 发布虚拟事件，KVM 负责递送。部分图形内存仍可直接访问，不是每个数据字节都经 QEMU 模拟。集成 GPU 的 A、B 和 batch 使用系统内存后备页，不能画成独立显存。参见 GVT-g 的访问与地址空间说明。

VFIO 是设备访问、DMA 和中断的框架；mdev 是 mediated 实例及厂商设备实现，SR-IOV VF 是硬件提供的虚拟功能，virtio-gpu 则是另一种前后端协议。它们不能直接互换。闭源厂商调度与固件内部不在这两个可核验实现的范围内。

源码与相关内容

演示中的源码路径按执行上下文展示关键函数。GPU 执行以命令包与硬件边界标识，不伪造内部 C 函数；宿主中断、KVM 递送、Guest 驱动和用户态等待也不串成一条同步调用栈。

  • AMDGPU CS 提交、DRM 调度回调、SDMA 4.0 doorbell与CS 等待。
  • GTT 中的 SDMA ring、QEMU VFIO BAR 映射与被捕获的 region 写。
  • VFIO MSI eventfd、KVM irqfd 路由与VM-entry 注入。
  • GVT-g ELSP 提交、命令审核与调度、完成交接与虚拟事件。
  • VFIO 直通与 DMA 映射、内存访问与 MMIO、中断递送及virtio-gpu 的独立协议路径。
