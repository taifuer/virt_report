序言

中断让设备在有工作时通知 CPU。网卡把收到的帧写入内存，再发出通知；驱动可以在两次收包之间让出 CPU。虚拟机也需要这项能力：客户机为自己的设备分配中断并选择目标 CPU，宿主把事件送到相应的 vCPU，即使它此时正排队等待运行。本文以 x86 的 QEMU/KVM 为例。

从中断线到硬件递送

这里有两条历史线索。客户机看到的接口从共享中断线扩展到带地址和向量的消息；宿主的变化则是把控制器、通知和递送逐步交给内核与硬件。今天一块 virtio 网卡可以同时使用 MSI-X、irqfd 和 APICv，三者分别管消息格式、通知入口和 CPU 递送。

时间或阶段变化及其原因
PC 与 PCI 设备接口传统 PIC 汇集有限的中断线；多处理器系统用 I/O APIC 把引脚路由到各 CPU 的 Local APIC。PCI INTx 可共享中断线，驱动需要辨认中断源。MSI 用内存写事务发消息，MSI-X 允许独立配置和屏蔽多个表项，多队列设备可以把工作分给不同 CPU。
2007—2008 · 内核 LAPIC2007 年的 KVM 补丁把高频访问的 Local APIC 移入内核；2008 年 Linux 2.6.25 的发布树中已有这套实现。控制器访问可以在 KVM 内处理，宿主内核中的设备后端也有了直接提交通知的入口。
2009 · Linux 2.6.32irqfd 将 eventfd 绑定到 KVM 中断路由。内核或独立进程中的设备后端可以自行触发完成中断，QEMU 负责事先配置路由。
2013 · Linux 3.10Intel VMX 路径已支持 posted interrupt：KVM 把向量登记到目标 vCPU，处理器可以在客户机运行期间完成交付，减少为了注入中断而发生的退出。
2016 · Linux 4.4Intel VT-d 的设备中断 posting 将这条路径延伸到直通设备。IOMMU 可以把设备发出的向量直接记入 vCPU 的待处理状态，省去逐次进入宿主设备中断处理程序的成本。

配置设备中断：队列、向量与目标 vCPU

网卡收包用到的两条路径

设客户机在 virtio-net 接收队列 0 中放好缓冲区，并将该队列关联到 MSI-X 表项 2。客户机 PCI 子系统配置表项，使它向 APIC ID 1 的 vCPU 发送向量 0x51。收到一个帧时，数据路径负责把帧和完成记录写进客户机 RAM；中断路径负责叫醒能够处理它的 CPU。一个中断可覆盖多个帧。

{{ diagram('interrupt-delivery-overview', '同一帧的缓冲区与中断去向', '报文留在接收缓冲区；CPU 取得中断向量后，由驱动读取队列，找到已完成的缓冲区。') }}

虚拟控制器的分工取决于平台。x86 的 in-kernel irqchip 在 kernel-irqchip=on 时把 PIC、I/O APIC 和每个 vCPU 的 LAPIC 都放在 KVM；split irqchip 把两个引脚控制器放在 QEMU，LAPIC 仍在 KVM。MSI-X 消息按地址与数据选择目标 LAPIC，直接绕过 I/O APIC 引脚。宿主上的物理 CPU 编号和客户机的 APIC ID 独立，vCPU 线程换核后仍使用原来的客户机编号。

设备侧：发布接收结果，发出 MSI-X

假设这次写入 1500 字节帧与 12 字节网络头，共 1512 字节。队列长度为 8，链头为 3，先前的 used.idx = 7。QEMU 填好缓冲区和完成项，通过写屏障保证两者可见，再把 used.idx 推进到 8。此时轮询队列的驱动已经能取到帧。

used.ring[7] = { id: 3, len: 1512 }
used.idx     = 8

设备接着检查驱动的通知偏好。未协商 EVENT_IDX 时，驱动可以用 VRING_AVAIL_F_NO_INTERRUPT 抑制通知；协商后，通过 used_event 指定需要通知的位置。本例中，索引从 7 进到 8，阈值为 7 时要通知，为 8 时这一项暂缓。驱动结束轮询、重新打开通知时会再查一次队列，以接住切换期间发布的完成项。

MSI-X 表项与屏蔽

本例采用 xAPIC 物理目的地和固定投递。表项 2 的地址为 0xfee01000（目的 APIC ID 1），data 为 0x51（客户机向量）。QEMU 的 msix_notify() 读取该表项。若表项或设备的所有向量被屏蔽，这次通知保存在待发位 PBA[2]，解除屏蔽后补发；否则 QEMU 经 KVM_SIGNAL_MSI 把地址和 data 一起交给 KVM。PBA 每个表项只有一位，实际完成了几个报文要读 used ring。

CPU 侧：从待处理向量到驱动收包

以 Intel VMX、内核 LAPIC、软件注入为例。KVM 解码 MSI 消息，选中 APIC ID 1，在中断请求寄存器设置 IRR[0x51]。若 vCPU 正在休眠，宿主需要唤醒承载它的线程；若已可运行，还要等宿主调度。客户机清除了 IF、处于 STI/MOV SS 的 interrupt shadow，或当前 APIC 优先级较高时，向量留在待处理状态。

当 vCPU 可以接受该中断，KVM 将向量从 IRR 转入服务寄存器 ISR[0x51]，安排在 VM Entry 时注入。处理器成功进入客户机后，经 IDT 的 0x51 入口进入 Linux 中断分派。对本例的边沿中断，apic_ack_edge() 可以在执行设备回调前发出 EOI，清理 LAPIC 的服务状态。

{{ diagram('interrupt-software-delivery', '一次 MSI-X 从 QEMU 到客户机 NAPI', 'KVM 准备注入、CPU 进入客户机处理入口和驱动取走缓冲区，是三个不同的时点。') }}

接下来 vring_interrupt() 检查队列并调用已注册的回调；virtio-net 可以安排 NAPI 轮询。驱动从 used 项读出链头 3 和长度 1512，将私有消费位置从 7 推进至 8，把帧交给网络栈并补充空缓冲区。EOI 应答的是 LAPIC，used 记录的是设备完成，NAPI 才实际批量收包。

后端通知与硬件中断递送

后端通知：eventfd 与 irqfd

把收包交给 vhost-net 后，报文和 used 项由内核后端填写。为省去“后端叫醒 QEMU，再由 QEMU 注入”的往返，QEMU 用 KVM_SET_GSI_ROUTING 将 GSI 37 对应到表项 2 的 MSI 地址与 data，再用 KVM_IRQFD 绑定 eventfd 与该 GSI。后端触发 eventfd，KVM 就可以按路由找到目标。客户机重配表项时，宿主需要同步更新路由和绑定。vhost 的完成通知使用的就是这条通路。

独立的 vhost-user 后端通过 VHOST_USER_SET_VRING_CALL 取得 callfd，写入后触发相同的内核路由。反方向上的 ioeventfd 把客户机写设备门铃的动作交给后端。两个 fd 传递的都是通知；描述符和报文保留在共享内存。

CPU 辅助与直通设备的中断重映射

在支持 APICv 的 Intel CPU 上，KVM 可以把向量置入目标 vCPU 的 posted-interrupt descriptor（PID）中的 PIR 位图。目标 vCPU 正在运行时，处理器可以将待处理向量同步到虚拟 LAPIC 并向客户机递送。AMD 的 AVIC 也加速虚拟 APIC 操作，使用 AMD 自己的控制结构。

换成 VFIO 分配的物理设备后，普通转发与设备 posting 都使用 MSI-X。IOMMU 读取中断重映射表项（IRTE），校验请求来源。普通表项将消息投给宿主 CPU，例如向量 0xB1 进入 VFIO 处理程序，再经 eventfd/irqfd 转交。posted 表项则直接指向目标 PID，由 IOMMU 设置客户机向量 0x51 对应的 PIR 位，按需向 PID.NDST 指定的物理 CPU 发送 PID.NV（如 POSTED_INTR_VECTOR）。宿主通知向量和客户机 IDT 向量各自独立。

同一客户机向量的五条路径

配置谁登记待处理向量省去的中转
QEMU 直接 MSI，软件注入QEMU 提交消息，KVM 写软件 LAPIC IRR。作为对照：由 KVM 准备 VM Entry 注入。
vhost-user / DPDK，irqfd后端写 callfd，KVM 按路由写 IRR。完成通知直接进入 KVM。
irqfd 加 CPU 侧 posting后端写 callfd，KVM 写 PID.PIR。运行中的目标 vCPU 可以由硬件递送。
直通，普通重映射宿主 IRQ / VFIO → irqfd → KVM。普通路由也可在 CPU 侧结合 APICv。
直通，VT-d postedIOMMU 按 posted IRTE 写 PID.PIR。免去每次设备中断的宿主 IRQ / VFIO 转发。

网卡、NVMe 控制器或 GPU 采用哪条路，由平台能力和路由配置决定。设备 posting 需要中断重映射、CPU 辅助、VFIO irq-bypass 绑定，以及可投给单一 vCPU 的路由。vCPU 暂停执行时仍可保留 posted 路由：被抢占时保留 pending，阻塞时可走唤醒路径，迁核时更新 PID 的通知目的地。详见内核的单目标路由选择与调度处理。

中断延迟的分段观察

在客户机查看网卡的 PCI 地址、MSI-X 配置和各 CPU 的 IRQ 计数：

# 在客户机执行，只查询状态；将地址换成网卡的实际 BDF
lspci -nn
lspci -vv -s 0000:00:03.0
cat /proc/interrupts

MSI-X: Enable+ 说明客户机选择了 MSI-X，irqfd 和 APICv 的启用情况要在宿主核对。宿主的 /proc/interrupts 记录宿主 IRQ；客户机的计数记录客户机收到的通知。NAPI 可以在一次通知后消费一批报文。

观察到的状态重点检查
包已到后端，used.idx 未动是否有接收缓冲区，后端任务是否运行、是否已发布完成项。
used 已推进，驱动尚未消费区分 NAPI 正在轮询、通知被队列抑制，以及设备已有待补发的 MSI-X（PBA）。
向量已 pending，客户机 IRQ 计数未动核对目标、IF、APIC 优先级和 vCPU 获得 CPU 的时间；中断重映射故障另查宿主。
客户机 IRQ 增长，应用仍然很慢观察 NAPI 预算、驱动消费位置、网络栈与应用唤醒，而非继续调整注入路径。

总结

一次收包有四个可分别观察的时点：后端发布数据、设备发出通知、vCPU 接受向量、驱动取走缓冲区。MSI-X 决定向谁发消息，irqfd 决定后端怎样把事件交给 KVM，APICv 与 VT-d posting 改变向量的登记与递送方式。开启硬件加速后，通知合并、vCPU 等待调度和驱动批处理仍会影响应用看到的收包延迟。
