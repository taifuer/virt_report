CONTINUE = 0x020 只省略重复的块名，不省略偏移或内容；零页用 1 B 填充值代表 4 KiB。目的端收到这批后已有 A1 / B1 / C1 / 0；源端继续运行，本例随后将 A、C 写成 A2、C2。

ram_save_iterate() 编码页记录；目的端 ram_load() 按偏移写入。一次 PART 是一次发送批次，不等于完整的一轮预拷贝。

这不是一个 STOP section，也没有“暂停标记”写入迁移流。演示只改变源端执行状态，不发送记录块。

本例只展开一个 PIC。实际机器还有更多设备 FULL，CPU 与设备记录的先后取决于注册顺序，不能据此推断所有机器都先 CPU、后 PIC。

qemu_loadvm_state_main() 读到 EOF 后退出分发循环。它不是 TCP 关闭标记，也不是客户机启动指令；目的端还需完成装载收尾、运行状态与存储检查。

实际 N 由完整设备字段描述的 JSON 字节数决定，不能用这里的省略文本计算。接收端按长度读完诊断描述；JSON 不替代 CPU / 设备状态，也不参与重新创建整台机器。

{% endcall %} {% call panel('restore', '14 · 目的端恢复执行', '装载成功且允许自动启动的分支') %}

恢复的 CPU 对象同步到 KVM，设备装载与存储激活检查通过，保存的运行状态和 autostart 允许执行后，目的端才调用 vm_start()。此时目的端使用 A2 / B2 / C2 / 0、RAX / RIP 及 PIC 状态继续运行。

源端保持停止并进入迁移完成状态，不能与目的端同时执行同一虚拟机。若禁用自动启动或保存的是暂停状态，成功迁入也可以保持暂停。
