场景与边界

一条客户机访存指令可以直接由硬件完成，也可能停在客户机页表、EPT 或宿主后备页这几个不同位置。演示沿同一组 RAM 地址切换条件，观察由哪一层处理、修改哪份结构，以及原指令在何时完成。

RAM 示例沿用EPT 缺页处理中的地址：GVA 0x40203080 → GPA 0x00403080 → HPA 0x21000080，页大小为 4 KiB。内存槽从 GPA 0x00400000 开始、长度为 2 MiB，后备 HVA 基址为 0x7f0000000000。因此目标页是槽内第 3 页，对应后备页 HVA 0x7f0000003000。

硬件执行两级转换；HVA 则用于 KVM 解析宿主后备。映射建立后，正常访存不会逐次经过 QEMU 的 HVA 查询。设备访问分别展示 QEMU 模拟寄存器、KVM 内核 LAPIC、ioeventfd 门铃，以及 VFIO 物理 BAR 和 ivshmem 共享 BAR 的稳态读取；通过 BAR 访问不代表最终落点一定是物理设备。

先选“RAM 内存”或“MMIO / 设备内存”。RAM 主路径保留正常访问、Guest 缺页和首次补建 EPT；宿主换页与脏页写保护放在默认收起的进阶入口。换页可能发生在 KVM 取后备页的过程中，写保护则处理已有映射的权限，两者不是与“补建 EPT”完全互斥的同级模式。每个示例固定其他前提，单独观察一处差异。

源码采用 QEMU 10.2.0、Linux 6.18，处理器采用 Intel VMX / EPT。普通 RAM 场景均使用 HVA 后备内存，未加入嵌套虚拟化或私有内存。具体前提位于演示下方的“当前场景配置与源码版本”；步骤间隔不表示实际时延。

地址空间与访问分派

Guest 资源语义与硬件地址转换

Guest 内核从固件内存图获知 RAM 范围，通过 PCI 枚举和 BAR 资源获知设备窗口。驱动选择适当的映射、缓存属性与访问接口，例如 ioremap()、readl() / writel()；它通常知道自己在访问 RAM、设备寄存器还是设备暴露的内存，但无需知道宿主 HPA。普通应用也不必了解这些后备细节。Linux 设备访问接口

在本例 x86 环境中，RAM 与 MMIO 都由普通访存指令触达。CPU 按地址转换、权限和内存属性执行：Guest 页表得到 GPA，EPT 得到 HPA，物理地址译码再选择内存或设备窗口。缓存属性约束访问行为，资源类型由映射与平台地址布局共同确定。

QEMU 配置地址空间，KVM 处理退出

QEMU 用 MemoryRegion 建立客户机物理地址布局：普通 RAM、共享后备和需要设备回调的区间具有不同属性。MemoryListener 将可映射的 GPA 区间及 HVA 后备注册为 KVM memslot。VFIO 可映射设备区域也可使用 RAM-device 接口，因此“存在 memslot”不等于“物理落点必然是普通 RAM”。memslot 注册、RAM-device 后备接口

EPT 缺项或权限问题使处理器退出到 KVM。普通 RAM 缺项由 KVM 取得后备 PFN 并补建 EPT，必要时由宿主内存管理先提供页面。需要模拟的访问先尝试内核 LAPIC / MMIO 总线；不能在内核完成的部分通过 KVM_EXIT_MMIO 返回 QEMU，由地址空间分派找到设备回调。EPT 由 KVM 管理，QEMU 负责相应设备操作；未分配的地址空洞也可能没有可处理的设备。EPT 建图、模拟访问分派、用户态 MMIO 请求

HPA 可以指向 RAM，也可以指向设备窗口

访问对象Guest GPAEPT 输出的 HPA实际落点

两个 BAR 示例使用相同 Guest 地址表示两种独立配置，便于对照。VFIO 的 HPA 指向宿主设备 MMIO 窗口。本例宿主 BAR0 的 CPU 物理资源基址为 0xd0000000，加上窗口内 offset 0x1000 即为目标地址。示例宿主桥采用恒等窗口；其他平台可能还需换算 CPU 物理地址与 PCI 总线地址。CPU 物理地址、总线地址与宿主桥

ivshmem 的 BAR2 则将共享内存对象暴露给 Guest。它没有真实 PCIe 设备，不需要 VFIO，也不逐次执行 QEMU 寄存器回调；BAR0 控制寄存器是另一片区域，不能由 BAR2 推断整个设备都无退出。普通 Guest RAM 同样不会因为启用了 VFIO 就自动指向 BAR。设备主动 DMA 访问内存时，才涉及另一个方向的 IOMMU 地址链。BAR0 与 BAR2 的注册、ivshmem 设备规范

普通 TLB miss 只说明转换缓存没有可用条目。Guest 页表和 EPT 都有效时，硬件能够自行完成遍历。CPU 数据缓存则保存数据或指令，其命中情况与转换缓存要分别观察。

Guest #PF 示例选用合法匿名映射的首次写入，由客户机内核处理；非法地址与权限错误可能终止应用。宿主缺页示例选用未启用 KVM 异步缺页协议的同步换入，由宿主内存管理提供后备页；在其他配置中，KVM 可以把等待转成异步处理。

后拷贝迁移中的 RAM 缺页还需要用户态参与：userfaultfd 通知 QEMU 缺页处理线程，由它向源端请求尚未到达的页面；补齐后 KVM 继续建立映射。QEMU 在此负责提供数据页，KVM 负责 EPT；具体过程见QEMU 后拷贝迁移及后拷贝机制说明。

只有交给用户态的 MMIO 读才需要这次往返：kvm_run.mmio.data 已填好时，Guest 寄存器仍可能保留旧值，用户态需重新进入 KVM_RUN，由内核先完成待决操作。KVM 在此之前会尝试内核 LAPIC 与 MMIO 总线；命中的 ioeventfd 写通知也可在内核完成。相关执行循环见KVM vCPU 运行与退出。

VFIO 直接访问只适用于允许映射的 BAR 区间，且本例从映射已建立的稳态开始。MSI-X 表、需模拟区域、首次映射缺失与权限变化不属于这条无退出路径。这里的 CPU 地址链是 Guest 页表与 EPT；设备自身发起 DMA 时使用的 IOMMU 地址链是另一个方向，不能串成一次 CPU 读取的必经环节。

映射管理与取舍

影子页表把 Guest 虚拟地址到宿主物理地址的关系合并到一套硬件可用的映射中，KVM 需要跟踪 Guest 页表的修改。EPT 将第二级转换交给硬件，使 Guest 更直接地管理自己的页表；新增的转换层级也带来页表遍历和缓存压力。TLB、页表遍历缓存与大页共同降低重复转换成本，代价涉及缓存失效、页粒度与内存布局。

按需建立 EPT 可以避免启动时为未访问页面做全部工作，首次访问则需要承担建图开销。宿主继续管理后备页，使换出、迁移和内存回收能够生效；这些变化要求 KVM 撤销旧映射，防止 Guest 沿失效 HPA 继续访问。映射生命周期见EPT 缺页与宿主后备页，QEMU 的 RAM 注册过程见MemoryRegion 与地址空间。

迁移期间还需要知道哪些页面被修改。演示选择软件写保护与位图这一条路径，优点是按页发现首次写入，代价是额外退出、记录与下一轮跟踪。硬件 PML 和 Dirty Ring 分别改变脏页发现或交付方式，不能直接套用本例的每一步行为。
