前言

virtio 后端完成请求后，把结果写入客户机内存中的 used ring，再根据通知条件向客户机发出中断。中间经过队列通知策略、PCI MSI-X 消息和虚拟 APIC；客户机驱动最终仍要读取队列，才能知道哪些请求已经完成。描述符提交与后端处理见virtqueue 的数据结构与操作。

本文跟踪现代 virtio-pci 设备的一个 split virtqueue，采用 x86、内核 irqchip、QEMU 用户态后端的普通通知路径。示例在非 IOThread 的设备处理上下文中直接发送 MSI-X；guest notifier 与 irqfd 是后文单独分析的替代路径。APIC 状态转换先按软件注入路径展开，再讨论硬件辅助。

完成记录与中断路由

同一个请求会经过几套编号。队列号选择设备的工作队列，MSI-X 表项索引选择一组消息配置，消息中的 APIC 向量选择客户机中断入口，irqfd 的 GSI 则选择 KVM 中断路由。它们之间由配置建立关联，数值无需相等。

发布 used 与判定通知

设队列大小为 8，先前 used.idx = 7，本次完成的描述符链头为 3。QEMU 先写完成项，再推进索引。若设备向驱动可写缓冲区写入了 512 字节，本次记录如下：

used.ring[7 % 8] = { id: 3, len: 512 }
写屏障：先让完成数据与完成项可见
used.idx = 8

驱动读取：last_used_idx = 7 → 消费 ring[7] → last_used_idx = 8

len 表示设备写入缓冲区的字节数；纯发送请求可以为 0，不能把它统一当作报文长度。virtqueue_split_flush() 在更新 used.idx 前执行写屏障；virtio_split_should_notify() 在读取通知条件前执行内存屏障。发布完成和决定通知是两个动作。完成发布、通知判定

未协商 EVENT_IDX 时，设备查看驱动设置的 VRING_AVAIL_F_NO_INTERRUPT。协商后，驱动用 used_event 表示希望被通知的完成位置，设备按 16 位环绕运算判断本次推进是否越过阈值：

need_event = (uint16_t)(new - event - 1) < (uint16_t)(new - old)

old = 7, new = 8, event = 7 → 0 < 1，发出通知
old = 7, new = 8, event = 8 → 65535 < 1 为假，暂不通知

这里假定 QEMU 已有有效的先前通知判定位置；首次尚未建立该记录时，代码会允许通知。通知抑制保留全部 used 记录，供驱动批量消费或轮询。驱动准备停止轮询时，需要重新启用通知并再次检查队列，处理“设备恰好在重新启用期间完成请求”的竞争。单纯打开中断后立即睡眠，可能错过已经发布的工作。

调大批处理范围可以减少通知与唤醒，但请求可能等到下一次轮询或通知才被消费。完成延迟因此同时受后端处理、通知策略和客户机调度影响。只统计中断次数，不能判断 I/O 是否更快。

MSI-X 消息与屏蔽状态

通知被允许后，virtio_pci_notify() 用队列配置的表项索引调用 msix_notify()。假设表项 2 已分配、MSI-X 已启用、功能级和表项级屏蔽均关闭，使用传统 xAPIC 消息格式、物理目的地、fixed delivery、edge trigger，向 APIC ID 1 发送向量 0x51：

MSI-X table[2]：
  address_lo     = 0xfee01000  // 0xfee00000 | (APIC ID 1 << 12)
  address_hi     = 0x00000000
  data           = 0x00000051 // vector = 0x51，fixed、edge
  vector_control = 0x00000000 // bit 0：表项屏蔽位，当前为 0

地址选择中断目的地，data 编码向量和投递属性。这次写入针对客户机的中断消息地址空间，不会把 0x51 写入一页普通客户机 RAM。x2APIC 扩展目的地、逻辑目的地或中断重映射使用不同的编码与转换，不能直接套用这个数值示例。

QEMU 从表项组装 MSIMessage { address, data }，经 PCI 地址空间写入进入 KVM APIC 的 MSI 区域，最终用 KVM_SIGNAL_MSI 提交 struct kvm_msi。此直接路径携带消息本身，不需要先为它分配示例中的 GSI 37。MSI-X 发送、KVM APIC 消息入口

若表项被屏蔽，QEMU 设置 Pending Bit Array 中该表项的 pending 位，暂不发送。取消屏蔽时发现 pending，会清除该位并补发通知。一个 pending 位可以合并多个完成事件；准确完成数仍在 used.idx 与 used ring 中。PBA 既不保存请求列表，也不能替代完成队列。

这个屏蔽与 virtqueue 的通知抑制处于不同层。前者已有一次待发送的 MSI-X 通知，后者可能根本没有产生该次通知；LAPIC 接收后暂不能投递，又是第三种等待状态。排查“完成了但客户机没处理”时，需要分别查看。

从 LAPIC 待处理中断到驱动回调

KVM 把 MSI 地址和 data 解码为目的 APIC、向量、投递方式等字段，再送到目标虚拟 LAPIC。以未启用 APICv 的 Intel VMX 路径为例，vmx_deliver_interrupt() 设置 IRR[0x51]，请求事件处理并 kick 目标 vCPU。kick 用于促使 vCPU 及时检查状态，不保证客户机立即执行中断处理函数。

此处的 ISR 是 LAPIC 的 In-Service Register。virtio-pci 另有名为 ISR 的设备状态字节，两者没有同一含义。MSI-X 模式下，驱动可依据分配的中断关联找到队列；无需把读取 virtio ISR 字节当作所有 MSI-X 完成处理的必经步骤。

irqfd 的替代通知路径

QEMU 为 guest notifier 配置 irqfd 时，先通过 KVM_SET_GSI_ROUTING 建立 GSI 37 到 MSI 地址及 data 的路由，再通过 KVM_IRQFD 绑定 eventfd 与 GSI 37。struct kvm_irqfd 的 fd、gsi、flags 和 resamplefd 均为 32 位字段；本例边沿 MSI 路径不使用电平中断的 resamplefd 应答协议。

后端发出 eventfd 事件后，KVM 的 irqfd_wakeup() 读取事件并尝试用缓存路由直接投递；当前上下文无法完成时，再安排工作队列。这样可以省去“用户态监听完成事件，再调用 MSI 注入接口”的中转。eventfd 计数不等于客户机应收到同样次数的中断，请求完成仍以队列为准。

QEMU 10.2 的 virtio_irq() 在 IOThread 中使用 guest notifier；非 IOThread 的普通路径调用 virtio_notify_vector()。vhost 的完成通知也可以接到 eventfd，但其后端执行者已经不同。irqfd 路径必须随 MSI-X 路由修改、屏蔽、解除绑定同步更新，不能绕开这些设备语义。

irqfd 描述的是 eventfd 到虚拟中断的内核接口。硬件 posted interrupt 则属于后续的中断投递优化；是否启用还受处理器能力、虚拟机配置及 KVM 当前状态限制。使用 irqfd 并不自动意味着完全绕过宿主软件，更不保证没有 VM Exit。

通知路径的演进

INTx 以中断引脚和电平状态表达设备事件。共享中断需要驱动确认来源，设备还要维护拉高与撤销的状态。MSI-X 改用消息，并允许各表项独立配置目的地和屏蔽状态，更适合多队列分散到不同 CPU；同时增加了表项、pending 和亲和性配置的管理成本。

virtqueue 的批量完成与 EVENT_IDX 减少通知频率，irqfd 缩短宿主侧通知交接，APICv / posted interrupt 减少部分 APIC 模拟及投递开销。它们作用于不同阶段，可以组合，但不能相互替代。

机制改善的位置需要处理的约束
MSI-X设备与队列的中断分配，减少共享源检查向量资源、CPU 亲和性、表项屏蔽与 pending 一致性
通知抑制与批处理单位请求的通知、唤醒和中断次数批量与尾延迟权衡，重新启用时检查竞争
irqfd完成事件到 KVM 中断注入的用户态中转eventfd 生命周期、路由更新及屏蔽处理
APICv / posted interruptAPIC 操作模拟及部分中断交付硬件支持，vCPU 运行、阻塞与迁移状态的同步；不可用时回退

Linux 的 irqfd 引入提交记录了用 eventfd 连接中断注入的设计。当前 VMX 源码则同时保留 posted interrupt 和软件 IRR 两条路径：目标 vCPU 正在运行时可以借硬件同步待处理中断，未运行时仍需要唤醒或等待下一次进入。客户机的中断屏蔽、优先级与队列消费规则保持有效。
