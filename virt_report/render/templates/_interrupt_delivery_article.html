场景与边界

virtio 设备完成请求后，先把结果发布到共享队列，再按通知条件提醒客户机。以接收队列的一次完成为例，MSI-X 表项选择 APIC ID 1 和向量 0x51，KVM 将消息送入目标 vCPU 的中断状态，处理器在允许的时机进入客户机处理程序。驱动随后读取队列并取得结果。

MSI-X、irqfd 与 posted interrupt 处在不同层：MSI-X 是设备发送中断消息的机制，irqfd 是 eventfd 进入 KVM 的通知接口。APICv 是一组 APIC 虚拟化特性，其中 posted-interrupt processing 配合虚拟中断交付，优化 CPU 接受与交付向量的过程。直通设备的两条演示都使用 MSI-X，区别是消息随后经宿主转发，还是由 VT-d 直接写入 vCPU 的 PID；并非“MSI-X 与硬件投递二选一”。

示例采用 x86-64、Intel VMX、QEMU 10.2.0、Linux 6.18 与 DPDK 24.11。主菜单只比较五条正常路径：QEMU 直接 MSI、DPDK irqfd 软件注入、同一 DPDK 后端配合 posted interrupt，以及直通设备的宿主转发与 VT-d posted。屏蔽、通知抑制和 IF 等待保留在默认收起的进阶入口，不与后端路径混为一类。

两种 posted 路径共用 CPU 侧的 posted-interrupt processing，区别在上游是谁写 PIR：一个是 KVM 软件，一个是 VT-d IOMMU。不能把 APICv 与 VT-d posted 看成两种完全并列、互斥的中断方案。演示固定目标 vCPU 正在另一物理 CPU 上运行、IF 与优先级允许等条件，才展示无需为本次交付退出目标 Guest 的路径。

DPDK 的 callfd 是 eventfd 文件描述符，irqfd 是 KVM 对 eventfd 和 GSI 路由的绑定。QEMU 事先建立内存共享、MSI 路由，并经 VHOST_USER_SET_VRING_CALL 把 fd 交给后端；逐次通知由 DPDK 直接写入。SPDK vhost-user 也可使用同一类交接方式，这里不另加一套重复演示。

本例只生成一次完成事件。write(callfd) → irqfd → PIR / IRR → Guest handler 是它在不同层的推进；posted notification 是提示目标 CPU 检查 PID 的宿主通知，并非第二次设备完成。快速 irqfd 路由可在 eventfd 写调用内执行，不表示唤醒 QEMU 或另一个用户态监听线程。相比“后端通知 QEMU、QEMU 再转发”，这里省去了用户态中转；相比 QEMU 自己直接提交 MSI，不能只凭箭头数量断言性能高低。

直通设备的路径选择

同一块直通网卡、NVMe 控制器或 GPU，都可能采用上表两条 MSI-X 路径。不是按设备类型划分，也不是应用逐次 I/O 选择：宿主在设备绑定、路由建立或更新时配置 IRTE，IOMMU 按当前表项处理设备发出的消息。Guest 驱动仍配置 MSI-X 并处理设备完成，通常不需要感知宿主是否使用 posting。

VT-d 设备 posting 要求 IOMMU 与 CPU 具备相应能力，宿主启用中断重映射、APICv 与设备 posting，VFIO irq-bypass 绑定成功，且路由能投递给单一 vCPU。广播、多播及 NMI 等不适用这里的 posted 路径。posting 未启用、不可用或路由不满足条件时，使用普通 remapped IRTE 经宿主转发；已有 posted 路由不再满足条件时，KVM 可恢复普通模式。KVM 的路由条件与回退

宿主转发不等于 CPU 侧不能加速：消息经 VFIO / irqfd 进入 KVM 后，仍可由 KVM 写 PIR，使用 CPU 侧 posted 交付。演示中的宿主转发场景特意关闭 APICv，只为完整呈现软件注入过程；不能把这个固定示例当成宿主转发的必要条件。

EOI 只应答 APIC 服务状态。Linux 边沿中断路径可以先应答，再执行设备处理；virtio-net 还可把队列消费交给 NAPI。EOI 之后，完成记录可能仍未被驱动消费。演示因此把 EOI 与 last_used_idx 的变化分成两个步骤。

IF 关闭与表项屏蔽发生在不同位置。IF = 0 时，已经到达的向量可以留在 IRR；设备表项被屏蔽时，消息尚未发出，PBA 记录补发需求。恢复 IF 后还要考虑 STI / MOV SS shadow 和 APIC 优先级。只看“中断已发送”无法判断客户机何时执行处理函数。

MSI-X 表项 2、KVM 路由键 GSI 37、APIC ID 1、向量 0x51 各自标识不同对象。直接 MSI 路径每次提交地址和 data；irqfd 路径预先登记路由，再用 eventfd 触发该路由。配置变更时，路由与 notifier 绑定也要保持一致。

设备发出 remappable MSI 后，IOMMU 按索引查找 IRTE，并校验事务来源。普通 remapped 格式仍需要宿主 IRQ handler；设备 posted 格式把 Guest 向量和 PID 地址写入 IRTE，让 IOMMU 发布 PIR 并按 PID.NV / NDST 通知处理器。来源不匹配、索引无效或表项 Present 位未置位时，消息进入重映射故障处理。

中断路径的演进

把 LAPIC 放进 KVM 后，待处理向量、优先级与许多控制器访问可在内核中完成，减少用户态往返。在这一基础上，irqfd 缩短后端事件进入 KVM 的交接：后端触发 eventfd，KVM 按预登记路由投递，无需用户态逐次监听后再发起中断 ioctl。

APICv 继续优化控制器访问与 CPU 交付。posted interrupt 把待处理向量放进 PID 的 PIR，通知正在执行目标 vCPU 的处理器；硬件将 PIR 合入虚拟 IRR，再按客户机规则交付。示例中从“发布 PIR”到“进入 handler”的逻辑阶段分别显示，实际硬件处理不提供供软件任意插入的中间停顿。

“DPDK · irqfd + posted interrupt”由 KVM 设置 PIR；“MSI-X · VT-d posted”由 IOMMU 根据 posted IRTE 设置 PIR。后者减少的是设备中断逐次进入宿主 IRQ / VFIO / irqfd 的转发，不是替换 MSI-X，也不是完全移除宿主的配置和管理。

设备 posted 示例固定目标 vCPU 正在运行。暂时未运行不等于自动切回普通 IRTE：vCPU 被抢占时可保留 PIR pending、抑制通知并等待调度；可被中断唤醒的阻塞 vCPU 可使用宿主唤醒通知；迁核时需更新 PID 的通知目标。KVM 在调入时恢复通知状态并检查 pending，Guest 的 IF、shadow 和优先级条件仍然有效。这些调度处理与“路由不再满足 posting 条件而回退”是两回事，也不能据此承诺所有状态都无 VM-exit。调入时的 PID 维护、调出与唤醒处理

实际优化可以从“设备完成 → 通知产生 → LAPIC / PID pending → vCPU 执行 → 驱动消费”逐段计时。批处理减少通知数量，irqfd 减少通知中转，APICv 减少部分交付退出，CPU 绑定与调度影响运行机会；收益和代价应在各自对应的阶段评价。

  • Linux：irqfd_wakeup；IRR / ISR 转换；IF 与 shadow 检查。
  • Linux：posted interrupt 发布与通知；Intel SDM：虚拟中断交付、posted processing 与 EOI。
  • Linux：IRTE 来源校验；remapped / posted IRTE 切换；remappable MSI 索引格式。
  • Linux：VFIO MSI handler 与 eventfd；vCPU PID 与设备中断绑定；单目标路由条件与回退。
  • 中断虚拟化：从 PIC、APIC、MSI-X 到硬件辅助的演进；virtio 完成通知与 KVM 中断注入：消息字段、完整调用链与队列消费。
