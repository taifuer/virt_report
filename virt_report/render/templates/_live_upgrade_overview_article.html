更新承载软件，保留客户机的运行状态

虚拟机运行期间，QEMU、KVM 或设备支持代码可能需要修复和升级。热升级的目标是让新实现接管同一台客户机，保留内存内容、执行位置与设备状态，避免客户机重新启动。交接通常仍有暂停窗口，业务连接是否连续还取决于停顿、设备和外部网络。

QEMU、KVM 与 VFIO 的升级范围

关注对象替换或保留的内容典型路径
QEMU 热升级替换用户态 QEMU；宿主 KVM 实现继续运行，新进程重建 VM/vCPU 对象CPR-transfer 在同机进程之间共享 RAM、交接资源 fd，再恢复 CPU 和设备状态
KVM 热升级替换承载客户机执行的 KVM 实现，接管内核对象及运行状态Orthus / Dual KVM 允许新旧 KVM 共存，逐台交接；HyperFresh 和字节跳动方案也需要各自的专门改造
VFIO 设备连续性在 VMM 升级期间保留直通设备及 DMA、IOMMU、中断关联设备 fd 和映射保留、通知解绑与重绑，或设备支持的停止与恢复协议

VFIO 是把设备访问、DMA 隔离和中断交给用户态 VMM 的接口。这里讨论的“VFIO 热升级”是升级过程中的直通设备交接：它不等于可以在线替换任意 vfio-pci 驱动、厂商内核模块或设备固件。升级这些组件需要另行验证厂商能力、设备复位行为和资源保留条件。

准备、冻结、接管与清理

  1. 准备新实现：核对机器与状态格式兼容性，准备内存映射和后端资源；可提前完成的工作放在暂停窗口之前。
  2. 冻结旧实例：停止 vCPU，并按各后端协议收尾在途 I/O，建立可恢复的一致状态。
  3. 交接状态与资源：保留或转交 RAM、资源句柄，恢复 CPU 寄存器、设备状态、路由和定时器。
  4. 新实例继续执行：确认数据与通知路径可用后放行客户机；旧实例保持停止。
  5. 清理旧资源：新实例接管成功后释放旧对象，核对没有泄漏或残留的设备访问权。

跨主机迁移通常要搬运 RAM；同机升级有机会保留原内存后备，显著减少复制工作。用户态地址、对象指针及内核对象可能变化，所以仍需把持久的客户机状态与临时实现状态分开处理。

VFIO：保持 DMA 与完成通知连续

直通网卡可以在 vCPU 停止后继续 DMA 或产生中断。升级时需要核对三组关系：设备仍访问哪份 RAM；IOVA 经 IOMMU 映射到哪些后备页；完成通知接入旧 KVM 还是新 KVM。某一组提前失效，可能造成 DMA 故障、状态丢失或通知送错实例。

支持相应路径的 QEMU CPR 可以保留设备与 IOMMUFD 资源，并交接中断连接。已进入旧虚拟 LAPIC 的 pending 与设备尚未发出的通知处于不同位置，都要随状态或连接一起处理。Orthus 的直通设备交接也要解决执行切换期间的 DMA 和通知连续性。

同机升级可保留原物理设备；跨机迁移需要把设备状态导出并恢复到兼容目标设备。两种能力需分别验证。

验证兼容性、停顿与失败处理

新实例尚未执行时，方案可能允许继续使用旧实例；新实例已修改共享 RAM 或磁盘后，旧状态就不能直接恢复。需要分别测试准备失败、冻结后失败和接管后失败，并检查是否仍有设备访问旧映射、通知旧 vCPU。

暂停时间从旧实例停止到新实例恢复执行测量；业务恢复还受连接超时、网络和应用调度影响。确认状态与请求连续后，再评价暂停窗口和资源开销。
